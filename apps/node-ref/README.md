# Re:Cooplay 通信プロトタイプ

PC（Windows モバイルホットスポット親機）とスマホ 3 台をローカル Wi-Fi だけで接続し、
**HTTP / WebSocket の双方向通信・端末識別・切断検知・再接続・遅延**を実機で検証するための最小実装。
Minecraft への入力注入はまだ含まない。

## 起動

```powershell
npm install            # 初回のみ（ネット接続がある状態で）
npm start              # http://0.0.0.0:8080 で待ち受け
```

- PC のブラウザで `http://localhost:8080/host` を開く（ダッシュボードは PC 本体からのみアクセス可）
- Wi-Fi 接続用 QR を出したい場合は `config.example.json` を `config.json` にコピーし、ホットスポットの SSID / パスワードを書く
- スマホから繋がらない場合、管理者 PowerShell で `powershell -ExecutionPolicy Bypass -File scripts\allow-firewall.ps1` を実行（TCP 8080 をローカルサブネットからのみ許可）

## 構成

| ファイル | 役割 |
|---|---|
| `server.js` | HTTP 配信 + WebSocket (`/ws`)。スロット割当・入力受信・欠落検知・ハートビート・ログ |
| `public/index.html` | スマホ用コントローラー（十字・A/B・Enter・Esc、連続送信テスト） |
| `public/host.html` | PC ダッシュボード（Wi-Fi QR / 参加 URL QR、P1〜P3 の状態、ログ） |
| `logs/session-*.jsonl` | 全イベントの記録（後から遅延・欠落を分析する用） |

### 通信仕様（要点）

- スマホ → `hello {clientId}`：`clientId` は端末の localStorage に保存。参加順に P1(ホスト)/P2/P3 を割当、4 台目は `full` で拒否
- 一度割り当てたスロットは切断中も保持し、同じ `clientId` の再接続で元のスロットに戻る（ホスト自動交代なし）。解放はダッシュボードの「スロットをリセット」のみ
- `input {seq, button, state: down|up}` → サーバーは `ack` を返す。スマホ側で RTT（平均/p95/最大）と未 ACK 数を計測し、1 秒ごとの `ping` でサーバーへ報告
- サーバーは `seq` の飛びを「欠落」、逆行を「順序逆転」として端末ごとに集計
- 切断判定：WebSocket close、または **4 秒間メッセージなし**（Wi-Fi OFF では TCP close が届かないため）。切断時は押下中キーを解放扱いにしてログに残す
- スマホ側は切断時に自動再接続（0.5 秒〜最大 5 秒のバックオフ）、画面復帰時にも再接続

## 入力注入と疑似ゲーム画面

`http://localhost:8080/game` は Minecraft の代わりになるテスト用ゲーム画面。**OS が実際に受け取ったキーボード / マウス入力だけ**で動き、
キーボード・マウスの図に「誰（P1/P2/P3）の操作で押されたか」を色で表示する。サーバーからの注入通知と突き合わせて受信OK / 未反映・遅延・押下時間を集計し、結果は `logs/` にも残る。

| 進行 | 操作できる人 | スマホ → PC |
|---|---|---|
| ロビー / 一時停止 | P1（ホスト）のリモコンのみ | ↑↓←→ / Enter / Esc |
| 協力プレイ | P1 移動 | スティック → W/A/S/D、ジャンプ → Space、スニーク → Shift、ダッシュ → Ctrl |
| | P2 視点 | ドラッグ → マウス移動（感度調整可） |
| | P3 アクション | 攻撃 → 左クリック、使う → 右クリック、持ち物 → ホイール、E / Q |

- ホストの START / PAUSE / RESUME で切り替え。協力プレイ中に誰かが切断すると自動で一時停止し、押下中の入力をすべて解放する
- 注入モード: `OFF` / `テスト`（疑似ゲーム画面を選択中のみ注入）/ `常時ON`（実ゲーム用。選択中のウィンドウへ送る）
- 押下は最低 60ms、解放は最低 50ms 保持してから次へ進む（通信でまとめて届いた連打も 1 回ずつ認識させる。溜まるのは 4 回分まで）
- `RECOOPLAY_DRY_RUN=1` で起動すると実際には注入しない（自動テスト用）

### 通信の安定化

| 仕組み | 内容 |
|---|---|
| WebRTC 速達便 | WebSocket (TCP) は 1 パケット欠けると再送まで後続が止まるため、順序保証・再送なしの WebRTC データチャネルを併用。シグナリングは WebSocket、STUN/TURN なし。つながらなければ WebSocket のみで動作 |
| 入力の二重送信 | 押下/解放は WebSocket と WebRTC の両方に同じ番号で送り、PC は番号順に先着 1 回だけ処理（欠けた番号は WebSocket の到着を待つので順序は崩れない） |
| 視点の累積値 | 視点は「累積移動量」を 30Hz で送るので、パケットが欠けても次で取り戻せる。PC 側で到着の揺らぎに合わせて自動で滑らかに補間 |
| 無線の省電力対策 | 協力プレイ中は WebRTC で 50ms ごとに生存確認を送り、スマホの無線が眠るのを防ぐ（RTC の遅延計測も兼ねる） |
| 早期再接続 | サーバーから 3 秒無応答なら OS の切断検知を待たずに張り直す |
| 自動復帰 | 切断による一時停止は、全員が 15 秒以内に戻れば自動で協力プレイに戻る（ホストの PAUSE は対象外。ダッシュボードで OFF 可） |

## 実機検証チェックリスト

| # | 項目 | 手順 | 成功条件 |
|---|---|---|---|
| 1 | PC の親機化 | 設定 → ネットワークとインターネット → モバイル ホットスポット を ON | ダッシュボードに `192.168.137.x (ホットスポット)` が出る |
| 2 | オフライン動作 | PC の上流（Wi-Fi/有線）を切ってからホットスポット ON を試す | ON にできる / 既に ON のまま上流を切っても維持される |
| 3 | スマホ接続 | 3 台を PC の Wi-Fi に接続 | 「インターネットなし」でも接続を維持（Android はモバイルデータ OFF 推奨） |
| 4 | HTTP | 参加 QR を読み取る | コントローラー画面が開く |
| 5 | WebSocket | 開いた直後 | スマホに `P1`/`P2`/`P3`・「接続OK」、ダッシュボードに `join` |
| 6 | 同時通信 | 3 台で同時にボタンを押す | ダッシュボードで端末ごとに押下中キーが表示される |
| 7 | 切断検知 | 1 台の Wi-Fi を OFF | 約 4 秒以内に `disconnect ... heartbeat timeout` |
| 8 | 再接続 | Wi-Fi を戻して再読込 or 待つ | `reconnect`、元のスロット番号のまま |
| 9 | 安定性・遅延 | 3 台で「連続送信テスト」を同時実行 | 欠落 0、RTT p95 を記録（`logs/` にも残る） |

### よくある詰まりどころ

- **スマホから開けない**：ファイアウォール（上記スクリプト）、URL がホットスポットの IP (`192.168.137.1`) になっているか
- **ホットスポットを後から ON にした**：ダッシュボードの「IP 再取得」を押す（5 秒ごとに自動再取得もする）
- **Android が勝手に切れる / 別回線に逃げる**：「インターネットなし」の確認ダイアログで「接続を維持」を選ぶ、モバイルデータ OFF
- **iPhone**：プライベートアドレス設定やプライベートブラウズで clientId が変わると再接続扱いにならない場合がある
