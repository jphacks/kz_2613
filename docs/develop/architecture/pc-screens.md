# PC画面：主要3画面とゲームウィンドウ（提案）

[現行仕様・確認範囲](../../frontend-specification.md) ／ [開発資料](../README.md)

参考画像 `../design/pc-wireframe-draft.png` は「QRコード、人数表示」「選択画面」「操作項目分担」の3領域を示すワイヤーフレーム。最終UIではなく、詳細な画面遷移はユーザーによる個別の確定前。

1. **接続ロビー**：SSID・ネットワーク状態、参加URLとQR、最初の接続者がホストである表示、0〜3人の人数、P1/P2/P3、再接続の案内。Android/iOSではアプリ用QRを読む前にWi-Fi参加が必要な場合がある。
2. **ゲーム選択**：対象プロファイルを表示する。P0はゲームの手動起動を許容し、ランチャーの自動検出・起動はP2。ホストスマホからこの画面を使う場合、キーボードのフォーカスと方向・Enter・Escによる操作が必要。
3. **分担確認**：Minecraft固定分担（P1移動・ジャンプ・スニーク・ダッシュ、P2視点、P3攻撃・設置・持ち物）、準備状態・フォーカス保護を表示し、ホストがスマホからStartする。役割編集はP0対象外。
4. **前面のMinecraft**：Re:Cooplayの追加画面ではなく、実際のゲームウィンドウ。ホストスマホはPause/Resumeを保持する。Pause後はリモコンでゲームメニューを操作できるが、Re:CooplayのPause自体はMinecraftを自動停止しない。

各画面共通の状態表示・通知で、接続、対象ゲーム・フォーカス、モード、エラー、緊急停止を示す。導線に登場するというだけで複雑な設定・エラー専用画面を増やさない。ゲーム終了・選択へ戻る際も参加端末の役割とセッションを保持する。

**権限の状態とPCに表示中の画面を分けて扱う。** Startには3人の参加と対象の準備完了が必要で、UIから未確認のOS入力を開始してはならない。Windowsのフォーカスを安全に確認できなければStartを止め、手動操作を案内する。

## 実装（2026-10-24、Rust版・`apps/web-static/app.html`）

- デスクトップアプリ（`apps/desktop`）は `/app` を表示する。`/host` は診断画面として残す（`/app` のフッターから開ける）。
- ①参加：参加URLのQR（ホットスポットを優先）、Wi-Fi名（`config.json` にある場合）、参加人数、P1〜P3の接続状態と端末の種類。
- ②ゲーム選択：Minecraft（手動起動）と、検出したSteam・Epicのゲームを横3列の正方形のタイルで並べる（#94・#121）。タイルは画像（Steamのライブラリの画像を中央で正方形に切り抜く。ない項目は頭文字）と、その下に小さくタイトル・出所・「未検証」の印。左右で隣、上下で1行動き、Enterで分担の画面へ、Escで戻る。選ぶだけでは起動しない（起動は分担の決定の後、#109）。
- ③分担確認：固定分担とホスト管理権、開始の条件（サーバーの `canPrepare`・`canReady` をそのまま使い、理由を説明）。ゲームへの入力は初期値でON（対象のゲームが前面で協力プレイ中のときだけ送る）。緊急停止などで止まったときだけ「入力を再開する」を出す（#114）。
- 画面の移動はPCのマウス・キーボードに加え、ホストのスマホのリモコン（ロビー・一時停止中）でもできる（`remote` メッセージ、画面が前面のときだけ）。
- 協力プレイ中・一時停止中は、入力先の状態と次の操作を上部に表示する。フッターに入力先と緊急停止キーを出す。
- 表示ロジックは `apps/web-static/app-view.js`（純粋な関数）にまとめ、`node scripts/sim/app-view-test.mjs` で試験する。
- 上記はこのPCでの確認のみ。デザインは提案段階で、ユーザーの確定前。

## 2026-10-25の最新開始手順

ゲーム開始は参加人数から独立した二段階にする。P1またはPC画面で「ゲームを開く・準備する」を選ぶとpreparingへ進む。P1がメニュー・ワールドを準備した後、P1だけが明示Readyで3人分担操作を開始する。P2/P3は待機する。詳細な認可・入力停止条件は docs/develop/decisions/2026-10-25-two-stage-ready.md を参照する。以前のSTART説明と異なる箇所は本判断を優先する。
