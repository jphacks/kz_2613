## 2026-11-14 ユーザー判断

| 未確定だった点 | 決めたこと |
|---|---|
| プレイ中の上部と編集の入口（仕様 4-1） | 上はロゴと「⋯」だけの帯。「⋯」の中に「配置を編集」を置く。ゲーム名・担当は普段は出さない（読み上げ用にだけ残す） |
| 編集の終わり方（仕様 2-5・4-2） | 編集中は上の帯を「破棄・↶（元に戻す）・保存」にする。帯はヘッダーの真上に同じ高さで重ね、操作領域は縮めない |

## 仕様の確定項目への対応

| 仕様 | 実装 |
|---|---|
| 1-1 操作領域を最大限確保・プレイと編集で同じキャンバス | 未編集でも保存済みでも、プレイは `LayoutController`、編集は `LayoutEditor` で、どちらも `#genControls` いっぱいの同じ領域に同じ計算（`placeParts`）で置く。従来の流し込みの描画（`Controller`）は協力プレイ画面では使わない |
| 1-1 保存後の一致 | 同じ端末・向きでは、編集開始時・編集中・保存後・再読み込み後で、全部品の位置・幅・高さが一致する（撮影の仕組みで px 単位で確認） |
| 1-1 編集メニューは重ねて表示 | 上の帯・長押しメニュー・「⋯」メニューは、操作領域の上に重ねる |
| 1-2 ドラッグで移動・長押しでメニュー | 編集中だけ。約0.45秒・8px 未満で長押し（仮の値）。プレイ中の長押しはゲーム操作のまま |
| 1-2 PowerPoint 式のハンドル | 選ぶと8つのハンドル（四隅は幅と高さ、上下は高さ、左右は幅）。見た目は14px、指でつかむ範囲は36px |
| 1-3 スティックは正方形・ボタンと視点パッドは縦横自由 | データを版2にし、`w`（短辺に対する比）と `h`（長辺に対する比）を別に持つ。スティックは短い方にそろえ、四隅のハンドルだけを出す |
| 1-4 ほかの部品は固定、動かした部品だけ補正 | ドラッグ中に重なる場所では、いちばん近い置ける場所を点線の枠で示し、指を離すとそこへ収める。置ける場所がなければ元の位置に戻す。大きさの変更は、ほかの部品の手前（6px）・領域の端で止め、横と縦は別々に止める。編集画面では、ほかの部品を一切動かさない |
| 2-4 編集中の安全 | 編集開始で本人の押下をすべて離す。編集画面は実入力へつながない（撮影の仕組みで、編集中の送信が0件であることを確認） |
| 2-5 保存・破棄 | 「保存」まで正式の表示にも端末の保存にも反映しない。「初期配置に戻す」も下書きを変えるだけで、保存するまで確定しない |

## データ（版2）

```json
{ "schema": "recooplay.phone-layout", "version": 2, "game": "<操作定義のID>",
  "parts": [{ "id": "move:stick", "kind": "stick", "controls": ["act:forward", "act:left"],
              "x": 0.5, "y": 0.73, "w": 0.93, "h": 0.46, "hidden": false }] }
```

- `x`・`y` は、縦持ちの操作領域を (0,0)〜(1,1) とした部品の中心（本体基準は版1と同じ）。
- `w` は短辺、`h` は長辺に対する比。縦持ちでは `w=1` が領域の幅、`h=1` が領域の高さちょうど。
- 版1（`size` だけの正方形）は読まずに初期配置へ戻す。保存値は消さない（旧データの移行はP3。版1の方針のまま）。

## 初期配置の作り方

- 担当（`allowedControls`）の部品だけを、上から「視点パッド → ボタン → スティック」の帯に分けて領域いっぱいに並べる。
- ボタンは格子（6個までは2列、12個までは3列、それより多ければ4列）。端数は最初の段に回して横長にし、最初の段は他より1.3倍高くする。
- 担当外の部品は、それだけで別に並べておく（担当が変わったときの初期位置。同時には表示しない）。
- 全502定義・全担当・3種類の画面の大きさで、重ならず領域の外へ出ないことを試験で確かめている。

## 仮に決めたこと（仕様では未確定。実機で見直す）

- 長押し 0.45 秒・ドラッグ判定 8px・部品の間のすき間 6px・ハンドルの大きさ。
- 「外した部品を戻す」と「初期配置に戻す」は、編集中の上の帯の「⋯」に入れた（仕様 4-2・4-3）。
- 複製した部品・戻した部品は、元の位置にいちばん近い空きに置く。空きがなければ置かずに理由を示す。
- 視点の感度は、視点パッドの下側に重ねて残した（仕様 4-1）。
- ボタンはキー名を大きく、操作名（ジャンプなど）を小さく添えた（仕様 4-1。キー名を出す判断 #150 はそのまま）。
- 未保存のまま協力プレイ画面を離れたら、今までどおり変更を捨てる（確認ダイアログは出さない。仕様 4-2）。

## 確かめたこと・残ること

- 自動試験：`phone-layout-test` 15項目（初期配置の網羅、空き場所の探索、ぶつかる直前で止まるリサイズ、画面と本体座標の往復、編集とプレイの描画位置の一致を追加）。ほかの web の試験もすべて合格。
- 撮影の仕組み（dry-run のホスト＋headless Chrome、402×874、タッチの再現）：「⋯」→配置を編集→選択→ドラッグ（重なる場所でのスナップ）→ハンドルでの縮小・拡大（ぶつかる手前で停止）→長押しメニュー→複製できないときの案内→元に戻す→保存→再読み込みまで動き、位置が一致することを確認した。
- **未確認：** 実機（iPhone Safari・Android Chrome）での指の操作、長押しとスクロール・拡大の干渉、複数の指、safe area、ブラウザーのツールバーの出入りで領域の高さが変わるとき。**Award Day の前に入れる場合は、実機で協力プレイと編集を一度通すこと。** 前の判断（2026-11-11）では、デモの見た目を変えないよう未編集の人は従来の配置のままにしていたが、この変更で全員の初期配置が変わる。
