# ゲーム管理サービスと起動監視の分離（#180）

#173の製品分離を統合したmainと、#179の確定差分を基準に[設計監査](2026-11-05-game-service-plan.md)を実装した。`games.rs`の検出・登録形式・ランチャー起動と`focus.rs`のWindows処理は再実装しない。

`GameService`は差し替え可能な`GameBackend`へ、探索場所・検出・ファイル選択・前面観測・ウィンドウ存在・前面化・検出済みEntryの起動を委譲する。既定backendは従来の関数を呼ぶ。別スレッドへcloneしたサービスを渡し、Hubへは同じイベントで結果を戻す。手動登録と編集の検証・保存順・ID制限・制御文字除去/60文字制限もサービスへ移した。

選択IDの既知判定・表示名・入力先構築・Minecraft公式ランチャーのEntryを独立させた。Steam/Epicはinstall_dir、手動は完全な実行ファイル、内蔵項目はbase target、消えた項目は空の対象条件という既存規則を保つ。入力互換性を検証済みとは扱わない。

起動監視の`Launch::observe`は、現在の世代・状態と明示時刻、出現/前面化結果から無視・待機・完了を返す。90秒/300秒の期限一致時のtimeout、出現を期限より優先する順序、前面化拒否の5秒未満の待機、5秒一致からの手動案内、500ms監視を維持する。古い結果とWatchは外部操作をする前に拒否する。

Hubは管理接続の認可、選択とlineup、参加者/Ready、検出要求の重複抑止、起動世代の発行、対象切替・消失での全解放/視点破棄/epoch・自動復帰解除、ログと通知順序を保持する。ゲーム起動や前面化がReadyを代行することはない。サービスはHTTP/WSの新しい入口を持たない。

fake backendで外部呼出し、期限境界・拒否、手動保存、旧非同期結果と切替、前面喪失の全解放を検証する。Windows実入力、実際のSteam/Epic・Store/従来版Minecraftランチャー、実Alt+Tab・スマホ・配布先PCの受入は未実施。
