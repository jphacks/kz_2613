# ゲーム管理サービスの境界と安全停止の監査（#180）

## 対象と現在地

main `b3c0e88` の `hub.rs`、`games.rs`、`focus.rs`、通信試験と[ホスト仕様](../../host-specification.md)を照合した設計監査である。今回は製品コード・ゲーム対応数・UIを変更せず、サービス分離の実装完了とは扱わない。Windows実機を操作して検証した記録でもない。

## 呼出しと副作用の一覧

| 入口/処理 | ガード・状態・副作用 |

## 推奨する分離

Hubにはセッションの対象ゲームID、Ready/分担・参加者/lineup、入力許可、epoch、停止効果と通知を残す。別サービスには検出要求/完了、手動登録の永続化と選択、検出済みEntryからの起動要求、ウィンドウの存在/前面観測・前面化を置く。既存games.rs/focus.rsを下位アダプターとして再利用する。

純粋な起動監視の候補は `LaunchState` と明示時刻・世代を受け、保留/成功/失敗/期限切れ・次の監視予約を返す計算部。実行ファイルやウィンドウの操作は結果を受けて行う。検出結果と入力対象条件を組み立てる判断も、raw Entryをそのまま認可として扱わない。

非同期完了は対象ID・世代と照合し、ゲーム切替/終了/失敗で旧結果が新しいlaunchや対象を上書きしないことを確認する。現在の探索は単一実行＋保留再要求であり、存在しない検出世代を実装済みとは記載しない。新たな世代導入は必要性と現在の順序を比較して決める。

## 移動前に固定する試験

| 系列 | 対照と確認項目 |
|---|---|
| 選択と認可 | 未知/同一/別ID、スマホからの管理命令、決定前、coop/paused起動拒否。拒否時の現在launch/Ready/epoch/入力状態も比較 |
| 起動の寿命 | 起動中連打、旧Launched成功/失敗、旧LaunchWatch、選択変更/終了/再探索と完了競合。現在世代だけ反映 |
| 期限/前面化 | 明示時刻で90/300秒、5秒待ち、500ms予約を境界前/一致/後で検証。未出現/前面化拒否/手動復帰を区別 |
| 消失/復帰 | 全員のキー/ボタン保持・未処理視点・連打中に消失/場所変更。全解放・旧入力拒否・自動復帰解除、再検出後も停止維持 |
| 手動登録 | 同名別exe・同フォルダー別exeは拒否、完全パスだけ一致。キャンセル/非exe/保存失敗/名称正規化、ID以外のパスを公開しない |
| 探索 | fake Steam/Epic/Minecraft/manual、重複要求、保留再探索、件数と画像更新、対象消失、空一覧。検出と互換性検証済みを混同しない |

既存のgames/focus単体、fakeGames付きprotocol-sim、静的素材配信と配布zip検査を維持する。新しいFakeGameBackendで起動要求・前面化・観測を記録し、実ゲームを起動せず制御フローを確認する。ゲーム実機確認#38・配布実機#41を置き換えない。

## 保留理由・外部依存・再開条件

#173のセッション境界が未実装で、#170〜#172が同じHubの入力効果を段階分離中である。ここでゲームサービスを積むと、対象変更→全解放→epoch→再開許可の責任を親差分と同時に再編するため、未統合Stackを増やさない。現在は本監査と試験設計までを成果とする。

再開は、先行入力列のレビュー/統合でStackが短くなり、#173の判定と副作用の境界が確定し、最新mainで#169〜#173の回帰が成功したとき。最初に検出/登録の外部呼出しのみ、次に起動監視、最後に前面観測の実行境界へ分け、各PRで停止順序と差分を確認する。待ちだけで全体停止せず、スマホと計測の独立作業は先行した。

外部OS/ランチャーの実動作、Store版/従来版Minecraft、実SendInput、Alt+Tab、スマホ経由操作、配布先PCは未確認のまま保持する。mainマージ・Issueクローズ・正式リリースは実施しない。検証記録は[BUILD_LOG.md](../handoff/BUILD_LOG.md)を参照。
