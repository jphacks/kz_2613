# ローカル接続の方式と、ワンタップ化・Legacy AP の調査（#63）

- 日付：2026-11-15（Claude Code）
- 区分：調査の記録。**採用の判断ではない**。実際に AP を立てる試験（Windows の設定を変える操作）はしていない。

## 結論（要点）

1. 今のモバイルホットスポットの実装は、**インターネット接続がある前提**で動く。ホストは `NetworkInformation::GetInternetConnectionProfile()` から `NetworkOperatorTetheringManager` を作る（`apps/host-rs/src/netinfo.rs`）。会場にネット回線がない・PC がどこにもつながっていないと、アプリからホットスポットを読めず、ON にもできない。
2. 古い「ホストされたネットワーク」（`netsh wlan hostednetwork`）は、この PC の無線（MediaTek Wi-Fi 6E MT7922）では**非対応**だった（`Hosted network supported : No`）。最近の Wi-Fi のドライバーは対応しないことが多く、代わりの方式にはならない。
3. **Wi-Fi Direct の Legacy AP**（`Windows.Devices.WiFiDirect.WiFiDirectAdvertisementPublisher` の `LegacySettings`）は、上流の回線がなくても、普通のスマホが Wi-Fi としてつなげる AP を作れる方式。この PC には Wi-Fi Direct の仮想アダプター（`Microsoft Wi-Fi Direct Virtual Adapter`）があり、ドライバーとしては使える見込み。ただし未確認の点が多い（下の表）。
4. 「1回のスキャンで参加まで」（ワンタップ化）は、#165・#449 の検討どおり、Wi-Fi の QR だけでは URL を開かせられないので難しい。今の 2 つの QR（Wi-Fi・参加 URL）を残し、見せ方で分かりやすくする（#449）。

## 方式の比較

| 方式 | 上流の回線 | 普通のスマホからの接続 | この PC での状況 | 主な制約 |
|:--|:--|:--|:--|:--|
| モバイルホットスポット（今の方式） | **要る**（今の実装は、インターネット接続のプロファイルから作る） | できる（Wi-Fi の QR で参加） | 使えている（2026-11-13 の実機プレイ） | 回線がないと使えない。Windows の標準の接続台数の上限は 8 台。帯域・チャネルは Windows 任せ |
| ホストされたネットワーク（`netsh wlan hostednetwork`） | 要らない | できる | **非対応**（`Hosted network supported : No`） | 古い方式で、最近のドライバーは対応しないことが多い |
| Wi-Fi Direct の Legacy AP | 要らない | できる見込み（SSID・パスフレーズを指定して、普通の AP として見える） | Wi-Fi Direct の仮想アダプターあり。**AP を立てる試験は未実施** | アプリが動いている間だけ AP が続く。IP の割り当て（DHCP）の有無・アドレスの範囲、通常の Wi-Fi 接続との同時利用、5 GHz の可否、接続台数の上限は要確認 |
| 外部のルーター・会場の Wi-Fi | ルーターしだい | できる | ― | 機材と設定が要る。会場の Wi-Fi は端末どうしの通信（AP の隔離）を止めていることがある |
| USB（ADB reverse など） | 要らない | 開発用のみ | ― | 製品の接続手段にしない（2026-11-09 の判断） |

## 未確認の点（Legacy AP を採るなら、実機で確かめること）

- AP を立てたとき、Windows が DHCP でスマホに IP を配るか。配る場合のアドレスの範囲（今のホットスポットは `192.168.137.x` を前提に参加 URL を作っている）
- PC が通常の Wi-Fi につながったままでも、同時に AP を立てられるか（同じ無線の同時利用）
- Android・iPhone から普通の Wi-Fi として見えて、Wi-Fi の QR（`WIFI:T:WPA;S:...;P:...;;`）で参加できるか
- 接続台数（4 台＋予備）と、5 GHz で立てられるか
- 管理者の権限が要るか、アプリの権限（パッケージ化していないデスクトップアプリから WinRT の API を呼べるか）

## 手動での復旧手順（今の方式で、ホットスポットが使えないとき）

1. Windows の「設定 → ネットワークとインターネット → モバイル ホットスポット」を開き、共有元の接続（Wi-Fi か有線）を選んで ON にする。共有元がない（どこにもつながっていない）と ON にできない。
2. 共有元がない会場では、スマホのテザリングに PC をつなぎ、それを共有元にしてホットスポットを ON にする（スマホのデータ通信を使うので、使う量に注意）。
3. それでも使えなければ、外部のルーターを用意し、PC とスマホを同じルーターにつなぐ。参加 URL は PC 画面の「接続方法・URLを確認」に出るアドレスを使う。
4. 会場の Wi-Fi を使う場合は、端末どうしの通信が許可されているか（AP の隔離がないか）を先に確かめる。

## 次の Issue の候補（採否はチームで決める）

- Wi-Fi Direct の Legacy AP で、回線なしでも参加できるようにする（上の未確認の点を実機で確かめてから実装）
- 回線がないときに、PC 画面で「共有元の接続がないのでホットスポットを使えません」と分かるように案内する（今は情報が出ないだけ）
