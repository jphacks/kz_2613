# ホスト不在・リセット・自動復帰の判断（#223・#213・#225）

機能監査 #200 で確認した問題に対する、2026-11-06のユーザー判断を記録する。ROLE-04の「ホストの自動交代はしない」「枠の解放はリセットだけ」は、ロビーについてこの判断で置き換える。

## ユーザー判断

| 項目 | 判断 |
|:--|:--|
| ホストが戻らないとき | ロビーで15秒戻らなければ、接続中で最も若い枠へ自動で移す |
| ロビーの切断枠 | 15秒で解放する |
| 元のホストが戻ったとき | 権限は戻さず、参加者として戻す |
| リセット | 全員を切断し、自動で再接続しない |
| 自動復帰 | ~~ONとする。期限は15秒~~ → **2026-11-10に初期OFFへ変更**（下の追記） |

## 適用範囲

ホストの交代と枠の解放はロビーだけで行う。準備中・協力プレイ中・一時停止中は従来どおり枠を保持し、権限を移さない。入力が動く段階で再開の権限を変えると、安全条件が変わるためである。

一時停止中にホストが戻らない場合の復旧は、今回の範囲に含めない。リセットで全員を切断してやり直す。

## 実装の方針

P1がホストである前提は変えない。移る端末の枠データをP1へ移し、接続を4008で閉じる。スマホは通常の再接続で同じtokenのままP1として戻り、welcomeとWebRTCが作り直される。スマホ自身がホストを指定することはない。

P1が空のロビーで接続中の端末がいれば、枠の期限とは関係なく昇格する。P1が解放された後に別の枠だけが戻った場合に、ホスト不在のまま残さないためである。

## ホストの手動譲渡（2026-11-07、#233）

現在のホストがP1のスマホから、ロビーで接続中の参加者へ譲れる。相手の同意は不要とする。2つの枠を入れ替えて、両者を4008で閉じ、同じtokenで再接続させる。他の端末が自分をホストにすることはできない。

## 自動復帰の初期値の変更（2026-11-10、Q40・#225）

ユーザーは、通信断後のセッション自動復帰を**初期OFF**に改めた（2026-11-06のON判断を置き換える。ONの観測は試作品の事実として残る）。

- 通信が戻っても、ホストの明示RESUMEまで再開しない。旧保持入力（長押し・スティック・視点）は、指を離して新しく押すまで再開しない（Q26・#285）。
- ホストの明示PAUSE・緊急停止・入力先喪失は、設定のON/OFFによらず自動復帰しない。
- ロビーの15秒のホスト交代・枠解放は、この変更の対象外で、上の判断を維持する。
- 任意でONにできる。ONの場合の期限は15秒。ONの実機確認は未実施。

### 既存設定の移行（実装：`apps/host-rs/src/config.rs`）

- `config.json` の `settingsVersion` が2未満（版なし）の場合、`autoResume: true` が旧初期値の結果か明示操作か区別できないため、**一度だけOFFへ移行**し、`settingsVersion: 2` を書き込む（ほかの項目は保持）。
- `settingsVersion` が2以上のとき、`autoResume` は利用者が明示的に選んだ値として扱い、再起動してもOFFへ戻さない。PC画面の切替も、同じ形式で `config.json` へ保存する。
- 設定が欠落している場合はOFF。`config.json` がなければ作らない（切替を保存するときだけ作る）。保存に失敗しても、今回の動作は安全側（OFF）のままで、ログに残す。
- 版の書き込みに失敗した場合は、次回の起動で再度OFFへ移行する。

## 確認の範囲

自動試験とdry-runで確認した。実端末での交代、自動復帰の期限内外・初期OFFの明示RESUMEの系列は実機で未実施である（#39）。判断は採用の決定であり、実機の合格を意味しない。
