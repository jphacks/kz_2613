# 起動ごと・全員リセットごとの一時Wi-Fi

[#415](https://github.com/jphacks/kz_2613/issues/415) のBと、2026-11-15の利用者の要望（展示の全員リセットでもSSIDとパスワードを毎回変える）を、#562・#563 で実装した。この文書はその採用判断を記録する。終了時の停止（A）は [ホットスポットの停止](2026-11-14-hotspot-shutdown.md) を参照する。

## 採用したこと

- Re:CooplayがホットスポットをONにするときは、Windows 11 24H2 以降のセッション単位の設定（`NetworkOperatorTetheringSessionAccessPointConfiguration` と `StartTetheringAsync2`）で起動する。SSIDは `ReCooplay-` に乱数12桁、パスワードは乱数32桁で、起動のたびに作り直す。
- Windowsに保存された永続のSSID・パスワードは書き換えない。そのため、終了時や異常終了の後に元の値へ戻す処理は要らない。前回の値を保存したスマホは、名前が変わるので自動では接続しない。
- 起動前から利用者がONにしていたホットスポットは、所有せず、変更も停止もしない。
- セッション単位の設定がない古いWindowsでは、従来の起動に戻る。このときは永続の設定のまま動き、全員リセットでの切り替えはしない。
- PC画面の「接続中のスマホをすべてリセット」（PC本体の画面からだけ受け付ける）では、全員の枠と入力を無効にしてから、Re:Cooplayが起動したホットスポットだけを止め、新しいSSIDとパスワードで起動し直す。選んだゲームとそのプロセスは残す。
- 切り替え中と失敗時は、新しい接続を `4001` で閉じ、PC画面に参加URL・QRを出さない（古いQRを見せない）。失敗したときは、Windowsの設定を確認してリセットをやり直すよう案内する。リセットをやり直すと、もう一度切り替えを試みる。
- 切り替えが終わったら、ホットスポットのアドレスが付くまで待ってから新しいQRを出す（#573 と同じ待ち）。
- 一部の参加者だけの退出（`leave`、#546）ではWi-Fiを変えない。
- パスワードはPC本体の画面（ループバック）のWi-Fi QRにだけ渡し、ログや外部の画面には出さない。

## 確認した範囲

- 2026-11-16、非管理者のWindows 11とAndroid 16（Chrome）1台で確認した。アプリが起動したホットスポットは起動ごとにSSIDが変わり、終了時にOFFになった。先にONにしていた場合は、終了後もONのままだった（`notOwned`）。
- 全員リセットを3回続けると、毎回約3.6〜3.8秒で切り替わってSSIDが変わった。Androidは旧Wi-Fiから外れ、新しいQRのWi-Fiから参加し直せた。記録は `docs/develop/handoff/BUILD_LOG.md`。
- 未確認：iPhone、切り替えに失敗したときの実機表示、24H2より前のWindowsでの従来起動。
