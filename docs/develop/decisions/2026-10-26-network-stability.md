# 通信の途切れへの対策：協力プレイ中の低遅延の動作とBluetoothの注意

2026-10-26のユーザーの実機での切り分けに基づく（Issue #131）。インストーラーでの推奨設定は #132 で扱う。

- **観測：** PCでBluetoothイヤホンに音を流していると、スマホからの受信が約0.4秒ごとに200〜400ms止まり、溜まった分がまとめて届いた（ログの分析は #131）。開発PCのWi-FiとBluetoothは一体の部品（MediaTek MT7922）で、Bluetoothの音声がWi-Fiと無線の時間を分け合うためと考えられる。
- **低遅延の動作：** 準備・協力プレイ・一時停止の間だけ、Wi-Fiのメディアストリーミングモード（`WlanSetInterface` の `wlan_intf_opcode_media_streaming_mode`）を有効にし、ロビーで戻す。開いたハンドルを持っている間だけ有効で、閉じれば（ホストの終了を含む）元に戻る。PCの設定は書き換えない。開発PCで、管理者権限なしに有効にできることを確かめた。使えない環境では何もしない。dry-runではWindowsの機能を呼ばない。
- **Bluetoothの注意：** 既定の音の出力先のデバイスの列挙元（`PKEY_Device_EnumeratorName`）が `BTHENUM`・`BTHLE` ならBluetoothと判定し、PC画面に「有線のイヤホンかPCのスピーカーを使ってください」と出す。5秒ごとに調べる。音の内容は読まない。開発PCで「ヘッドホン (COTSUBU Patra BK)」を `BTHENUM` と判定した。
- **途切れの観測[H]：** 150ms以上空いた直後に3件以上が10ms以内にまとめて届いたら「途切れ1回」と数える（無線が止まって溜まった分が一度に届く形。何も送っていないだけの空白は数えない）。10秒ごとに、スマホごとの途切れの回数・最大の空白・往復時間（スマホが送るping の統計）をログ（`net`）に残し、直近10秒に3回以上のスマホがあればPC画面に注意を出す。IP・端末の識別子は残さない。

- **診断と案内（#70）：** PCの「操作設定」の「通信の診断」に、つながっているスマホごとの経路（WebRTC・WebSocket）、往復時間（平均・95%）、受信の途切れ、再接続の回数と、状態（良好・注意・不安定）を出す。判定[H]：途切れ3回以上/10秒で不安定、往復の平均100ms超か95%値300ms超で注意、WebRTCが開いていなければ注意、再接続3回以上で注意。対処は案内するだけで、PC・スマホの設定は変えない（Bluetooth機器を外す、PCのホットスポット（5GHz）につなぐ、近づける、ページを読み込み直す、スマホの省電力を切る）。スマホの接続・診断の画面にも、自分の通信が悪いときの案内を出す。
