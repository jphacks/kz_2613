# セッション判定と副作用の境界（#173）

先行11 PRを履歴保持のマージでmain `a3ffc413f6d80b169298207d86cae24bf111a9a4` へ統合した後の製品実装。既存の[設計監査](2026-11-05-session-extraction-plan.md)を基準にした。

`session.rs` はPhase・InjectModeと、観測済みの事実から拒否理由・要求可否・通常遷移案を返す純粋な判定を持つ。Ready/Resumeの理由列、P1限定コマンド、開始系だけのepoch一致、固定参加者、役割交換・担当、切断期限・自動復帰を単体検証できる。時刻は引数で受け、通信・OS・ログ・時計を呼ばない。新依存は追加しない。

Hubは接続の認証・現在接続とRTC世代の照合、事実の収集、前面化、入力解放と視点破棄、状態・epoch更新、ログ・通知を実行する。通常遷移の順序は全解放→視点破棄→phase/ロビー時の分担破棄→reason→epoch→ログ→低遅延モード→通知のまま。既にpausedのPAUSE再要求は通常遷移の冪等性へまとめず、全解放・epoch更新を維持する。追加のHub回帰でup通知がphaseログと新epochのgame通知より先に出ることを検証する。

Onでの前面化前の要求可否と、Testの現在の入力可否は区別する。理由の順序・文言、期限一致時の復帰許可、replacedによる停止期限非延長、非参加者切断でcoopを止めないことを保持する。PC monitorの準備には従来どおりPlayerのepoch境界を追加しない。通信契約や実機受入条件は変更しない。

SendInput解放失敗後の未再送は既存の別問題として[#191](https://github.com/jphacks/kz_2613/issues/191)で扱う。この抽出で失敗時挙動を変更しない。実機のAlt+Tab・ホットキー・Android/iPhone・Minecraftは未検証。
