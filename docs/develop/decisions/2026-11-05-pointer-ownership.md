# スマホの入力保持元を一元管理する（#177）

## 再現と変更の範囲

#176で実controllerの同一ボタンを2指で保持し、片方だけ離すと早期upになることを再現した。今回は構造分離に加え、この明示された不具合を修正する。UI刷新・通信形式変更・Rust側の変更は行わない。親は[PR #182](https://github.com/jphacks/kz_2613/pull/182)で、最新ユーザー判断に従うStacked PRとする。

## 責任境界

`input-owners.js` は保持元→control集合とcontrol→保持元集合を持つ。最初の保持元でdownの送信が成功した場合だけ保持を登録し、最後の保持元が離れたときだけupを要求する。同じ保持元の重複イベント、個別解放、保持元全体の解放、全解放は冪等にする。通信・DOM・epoch・役割の認可をこの部品へ混ぜない。

通常ボタンはpointerId、スティックはインスタンス固有のSymbol、タッチパッドのクリックは専用Symbolで所有する。ボタンを保持中の同じクリックのタップも、保持を早期解放しない。ボタンの押下表示は、その要素を保持する最後のPointerまで維持する。

controllerは送信可否・連番・メトリクス、入力部品はPointerとジェスチャー、所有部品は共有保持の集約を担当する。既存の `ctlDown` / `ctlUp` に内部の保持元引数を追加するが、ワイヤ形式は変えない。視点30Hz、累積値、WS/RTC二重送信、iseq/epoch、ホスト権限の処理は従来どおり。

## 停止・失効

既存のreleaseAllはタッチパッド・協力入力部品・全Pointerを解放してから所有部品の残りを全解放する。切断・epoch変更・画面再生成・非表示・回転・診断・ページ終了の停止経路を維持する。upを送れない切断でもローカル所有は失効し、再接続で旧押下を復元しない。サーバー側の切断時全解放は別の責任として維持する。
