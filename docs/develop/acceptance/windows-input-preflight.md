## 切替と実施順

- dry-runでは `RECOOPLAY_DRY_RUN=1` がWindows送出を短絡する。`test` は実入力を許可できるモードなので、dry-runとは別に扱う。
- 実入力開始の許可後に、専用ルートへ同じ版の画面と操作定義を置き、専用 `config.json` を `{"injectMode":"off","autoResume":false}` で作る。固定exeのハッシュを再照合する。新しいPowerShellで `RECOOPLAY_ROOT` を専用ルートに設定し、`RECOOPLAY_NO_CONFIG`、`RECOOPLAY_DRY_RUN`、`RECOOPLAY_FAKE_TARGET`、`RECOOPLAY_RUNTIME_MEASURE` 等の試験用上書きが継承されていないことを確認する。既存の本番設定は編集しない。ホストを起動してOFFを確認する。設定を読まない場合の既定値はONなので、OFFを確認できなければ直ちに終了する。
- PCの `/host` で「テスト」を選び、対象の `/game` だけを選択する。このモードの判定はループバックのゲーム画面が通知するフォーカス状態。実ゲーム用ONのWindows前面対象照合とは異なり、通知の遅れや別ウィンドウへの誤入力を監督下で確認する必要がある。
- 1回の短いSpaceから始める。押下と解放が対応し、別窓への入力がなければ、左右マウス→同時保持→Pause→無害な観測窓へのAlt+Tab→実ホットキーの順に個別に試す。段階ごとに押下、解除、再開前の空状態を記録する。
- `/game` はkeydown/up・mousedown/upとホストの通知を突き合わせられるため到達確認に使える。ただしblurで画面表示を消すので、表示だけでOSの解放は判定しない。ホストの解放ログ・未確認集合、別窓のイベント、同じデスクトップの読み取り専用の `GetAsyncKeyState` 上位ビット（例：SpaceはVK 0x20、左右ボタンは0x01/0x02）を別欄に記録する。物理入力を混ぜず、切替後に新規downが発生しないことも確認する。
- 異常時は `Ctrl+Alt+F12` →スマホの操作を離す→ホストの注入OFF確認→正常終了の順。物理キーやボタンに残留が見えたら、該当入力をPC上で押し直して離し、OS状態を再確認する。停止不能、対象外入力、残留、予期しない前面切替があれば系列を中断し、状態とログを保存する。
