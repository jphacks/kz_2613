[試行計画](../../wifi-comparison-plan.md)で、通信方式（`transport`）だけを変えた60秒×各3回の実Wi-Fi試行。既存の `pr274-wifi`・`pr274-wifi-after`・`wifi-periodic-ice-276` は上書きしていない。

## 結果

端末内のACK往復（ms、224操作）と、視点のホスト受信の200ms以上の空白（`look-gap-analysis.mjs`）。

| 通信 | 組 | ACK往復 p50 / p95 / p99 / 最大 | 200ms以上の空白 | 最大の空白（ms） | 視点の欠落 / 送信 |
|---|---|---|---|---|---|
| rtc-ws | 1 | 21.3 / 110.4 / 219.1 / 251.8 | 0 | — | 332 / 1730 |
| ws-only | 1 | 44.6 / 251.7 / 333.8 / 371.6 | 14 | 845.9 | 0 / 1752 |
| ws-only | 2 | 48.7 / 371.7 / 648.6 / 796.7 | 12 | 460.7 | 0 / 1751 |
| rtc-ws | 2 | 28.1 / 129.9 / 446.4 / 577.6 | 2 | 276.7 | 387 / 1726 |
| rtc-ws | 3 | 23.9 / 111.2 / 231.7 / 280.2 | 1 | 245.6 | 342 / 1723 |
| ws-only | 3 | 24.8 / 199.9 / 329.8 / 347.2 | 10 | 375.7 | 0 / 1748 |

- 6試行とも、runnerの全項目と経路照合が合格した。未ACKはない。
- **3組とも、RTC+WSの方がACK往復のp95が小さく（110〜130ms対200〜372ms）、視点の200ms以上の空白も少なかった（0〜2件対10〜14件）。** WS単独の空白はすべて「遅れて届いた（delayed）」で、欠落はない。RTC+WSの空白は、遅れと欠落が混ざった形（mixed）。
- RTC+WSでは、視点のパケットの約2割がホストに届かなかった。速達便（順序保証・再送なし）のため欠落しうる。視点は累積値を送るため、次のパケットで追いつく設計（`apps/web/src/shared/input/cooperative.ts`）。欠落が操作感に影響するかは、実ゲームで確かめる。
- 端末1台・同じ場所・同じ時間帯の連続試行で、電波状態は記録していない。dry-runなので、実ゲームでの体感は含まない。

## 試行のやり直し

最初の実行では、candidate2とbaseline2が、runnerの「同一ボタンの2接点保持」の確認で失敗し、視点の計測まで進まなかった。ホストには解放が届いており（押下から約500ms後）、押しっぱなしは残っていない。確認が、最後の指を離してから180msしか待たなかったため、Wi-Fiで遅れて届いた解放を取りこぼした。この2試行は、同じrunner（`c63a55c`）で、順序の最後にやり直した（両方とも合格）。確認の待ち方は、この記録と同じPRで直した。
