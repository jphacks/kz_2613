# 定期ICE観測の負荷比較（#276、2026-11-11）

[試行計画](../../wifi-comparison-plan.md)と[集計](../../wifi-overhead-summary.md)の手順で、5秒ごとのICE観測の有無を比べた最初の実Wi-Fiデータセット。既存の `pr274-wifi`・`pr274-wifi-after` は上書きしていない。

## 条件

| 項目 | 値 |
|---|---|
| ホスト | main `f21f5a0` のCI配布zipの `recooplay-host.exe`（manifestのcommitは `f21f5a0`、dirtyなし、SHA-256一致）。dry-run・no-config・疑似入力先で、OS入力なし |
| 画面の資産 | 同じ `f21f5a0`（未コミットの変更なし） |
| 端末 | Android 16（`25118PC98G`）・Chrome 156。1台 |
| 経路 | HTTP・WS・RTCはWindowsモバイルホットスポットのWi-Fi。USBはadbとCDPの制御だけ。全試行で選択ICE候補対とLAN経路を照合した |
| 比較軸 | `periodicIce`（ありがbaseline、なしがcandidate）。通信は `rtc-ws`、先行ACK観測なし、ホスト入力トレースあり |
| 試行 | 60秒×各3回。順序は baseline1 → candidate1 → candidate2 → baseline2 → baseline3 → candidate3 |

条件は [condition.json](condition.json)、生成した計画は [plan.json](plan.json)、集計は [summary.json](summary.json)。各試行の生記録（`summary.json`・`network.private.json`）はLANアドレスを含むため、リポジトリには入れずローカルに保管した。

## 結果（端末内ACK往復、ms）

| 組 | あり p50 / p95 / p99 / 最大 | なし p50 / p95 / p99 / 最大 | 差（あり−なし）p50 / p95 / p99 |
|---|---|---|---|
| 1 | 25.3 / 153.2 / 483.9 / 615.0 | 23.6 / 110.3 / 203.5 / 253.2 | +1.7 / +42.9 / +280.4 |
| 2 | 31.1 / 148.1 / 211.9 / 373.5 | 24.9 / 110.2 / 205.7 / 268.8 | +6.2 / +37.9 / +6.2 |
| 3 | 23.6 / 109.1 / 130.7 / 185.9 | 28.0 / 127.9 / 231.6 / 281.7 | −4.4 / −18.8 / −100.9 |

- 各試行の標本は224操作で、未ACKはない。6試行とも、runnerの全項目（入力の独立性能・保持中のPause・回転・バックグラウンド・切断と再接続での全解放など）が合格した。
- 差の向きは組によって逆になり、試行間のばらつきの方が大きい。**この3組からは、定期ICE観測が端末内ACK往復を悪化させるとは言えない。** 逆に、影響がないと結論づけるにも標本が少ない。
- ホスト内の受信→受理のp99は、1組目のありで367.6msと大きかった。ほかの5試行のp99は1ms未満（最大でも10.3ms）で、この1試行に固有の滞留とみられる。原因は未特定。

## 制約

- 端末1台・同じ場所・同じ時間帯の連続試行。電波状態は記録していない。
- dry-runなので、実ゲームでの体感や表示の遅れは含まない。
- ホスト入力トレースの有無（`hostTrace`）と先行ACK観測の比較は、まだ実施していない。
