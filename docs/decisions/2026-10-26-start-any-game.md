# 認識できたゲームなら、未検証の定義でも協力プレイを開始できるようにする

2026-10-26のユーザー判断「どのゲームでも認識できていればおそらく問題ない」に基づく（Issue #123）。#97・#99で決めた「未検証（template・extracted・unverified）の定義ではReadyを拒否する」より、この文書を優先する。

- **背景：** Readyを `reviewed`・`device` の定義だけに限っていたため、同梱502本のうち開始できるのはMinecraft（`device`）だけだった。操作定義から作るスマホの画面（#60）と、安全の条件（前面の確認・P1の明示Ready・緊急停止・状態変化での全解放・割り当てた操作だけを送る）はすでにあり、未検証でも試せないことのほうが問題だった。
- **開始の条件：** 確認の状態では制限しない。PC画面・スマホには「未検証。操作が届くか確かめながら遊んでください」と表示し続ける。分担できる操作がない定義（マウス操作だけの `pointer` 型 107本など）は、理由（「マウス操作が中心のため、スマホで分担できる操作がありません」）を表示して開始させない。
- **定義のないゲーム：** 同梱の定義にない検出したゲームには、3Dアクション型と同じ操作（WASD・マウスの視点・左右クリック・E・1・2・Tab）の汎用の定義（id `generic`、状態 `template`）を当てる。以前は、定義がないゲームを3人で遊ぶとMinecraftの固定のキーの表で送っていた（不具合）。固定の表はMinecraftの3人と診断用の疑似ゲームだけで使う。
- **弱めていない条件：** 入力は協力プレイ中・P1の明示Ready後・対象のゲーム（インストール先の実行ファイル）が前面のときだけ送る。緊急停止・状態変化での全解放は変えない。

## 未検証

- 実際のゲーム（Minecraft以外）での入力の到達（#61）。dry-runの通信試験だけで確かめた。
- 汎用の定義のキーが、個々のゲームの既定のキーと合うか。合わない場合は、ゲームの定義の追加（#98）・キー割り当ての編集（#50）で直す。
