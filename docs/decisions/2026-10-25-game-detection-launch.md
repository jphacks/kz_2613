# Steam・Epicのゲームを検出し、一覧から起動する

2026-10-25のユーザー判断に基づく採用判断（Issue #54・#93・#94）。[二段階開始](2026-10-25-two-stage-ready.md) の「一般ランチャー探索は導入しない」より、この文書を優先する。要件v0.3の11章ではP2だったランチャー検出を前倒しする。

- **範囲：** まずSteamとEpicのインストール済みゲームを検出する。GOG・Xbox・Ubisoftなどは後回しにし、それ以外は手動登録（#49）で受ける。
- **起動：** 選んだら起動する動作は、Minecraftなど特定のゲームだけでなく、選択画面に表示したゲームすべてに反映する（ユーザー判断）。Minecraft Javaは公式ランチャーで「プレイ」を押す必要があるため、自動起動の対象外とし手動起動を案内する（#55）。
- **分担：** ホスト側（検出 #54・起動 #93）と画面（#94）でIssueを分ける。
- **安全：** 画面からは項目IDだけを受け取り、起動URLは検出時に確かめた値（appid等、英数字と `._-` のみ）から組み立てる（#88の「任意の実行パスを受け取らない」を維持）。起動前に全解放・epoch更新を行い、協力プレイ中は起動しない。起動しても進行は変えず、P1の準備・Readyで開始する。
- **入力先：** 一覧で選んだゲームは、前面の実行ファイルがそのインストール先フォルダ内にあるときだけ注入する。
- **再検出：** 選択中のゲームが消失・移動したら全解放して旧入力・視点・起動待ちを破棄し、協力中なら一時停止する。未検出の選択をMinecraftへ読み替えず、再検出できても自動再開しない。
- **未検証の扱い：** 検出は入力が通ることを意味しない（要件11章5項）。一覧の項目はすべて `verified: false` とし、対応の判定は別に行う。チート対策や管理者権限のゲームでは合成入力が届かない場合がある。
- **選択画面（#94）：** 一覧は固定のMinecraft（手動起動）の後に `state.games` を並べ、`verified` がtrueでない項目に「未検証」を表示する。クリック・上下キー（リモコンの上下）は選択だけ（`select_game`）。選択だけで起動しないのは、リモコンで項目を移動するたびにゲームが起動しないようにするため。→ 起動は、メンバー・分担を決定した後の分担の画面へ移した（[起動を分担決定の後に移す](2026-10-25-launch-after-roles.md)、#109）。
- **プライバシー：** インストール済みゲームの一覧はPC画面にだけ送り、スマホには送らない。ログには、検出は件数だけ、選択・起動はIDだけを記録し、ゲーム名・インストール先は残さない。

PC上のdry-runシミュレーションで照合し、開発PCではSteamの検出とTerrariaの起動・前面化・入力先の判定を確認した（注入OFF）。検出したゲームへの入力（注入ON）は未検証。Epicの実機テストは、2026-10-25のユーザー判断で本PRの対象外とする（使える見込みの状態で可）。起動URLは、Epicのランチャーが作るデスクトップのショートカットと同じ形式（名前空間・カタログID・アプリ名）を使い、それがなければアプリ名だけの形式（Lutrisの設定例と同じ）を使う。
