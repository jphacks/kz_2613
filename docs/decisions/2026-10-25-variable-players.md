# 参加人数を2〜4人にし、人数に応じて分担する

2026-10-25のユーザー判断に基づく採用判断（Issue #57・#105）。[二段階開始](2026-10-25-two-stage-ready.md)・`protocol.md`の「必要人数は固定3人」、要件v0.3のROLE-03（必要人数1〜3、4台目は拒否）より、この文書を優先する。

- **人数の決め方（ユーザー判断）：** 2〜4人で遊ぶ。人数は、ホスト（P1）がReadyを押した時点で接続している人数で決める。P1を含めて2人以上でReadyできる。PC画面で人数を指定する方式は採らない。
- **枠：** P1〜P4の4枠。5台目は満員（`full`、4004）。ホスト権はP1のみで変わらない。
- **分担（ユーザー判断）：** 操作定義から自動で振り分ける（`profiles::assignment_for`）。Minecraftは、実機で確かめた3人（P1〜P3）のときだけ従来の専用画面と固定の表を使い、2人・4人、または枠が飛んでいる場合（例：P1・P2・P4）は、操作定義から作った画面（#60）を使う。結果は2人で「移動／視点＋攻撃・使う＋持ち物」、4人で「移動／視点／攻撃・使う／持ち物」。
- **参加者の固定[H]：** Readyの時点の接続者を参加者（`game.participants`）とし、分担とともに終了（END・ゲーム変更・リセット）まで固定する。協力プレイ中・一時停止中に人数が変わっても組み直さない（#105「勝手に組み直さない」）。
  - 参加者が切断したら一時停止し、その人が戻るまで再開できない（自動復帰も同じ条件）。人数を変えるときは終了して準備・Readyからやり直す。
  - Readyの後に来た人は今回は参加しない。入力は送らず、切断しても一時停止にしない。スマホには「次の開始から参加します」と表示する。
  - 以前は再開（RESUME）のときに、その時点の人数で組み直していた。ホストが新しい分担を見ないまま組み直されるため、固定に変えた。
- **表示：** PC画面の参加者は4枠、分担の確認は担当を表示する人数（参加者、なければ接続中の枠）だけ列を出す。誰も接続していないときは基本の3人の分担を見せる。

## 未検証・残り

- 2人・4人のMinecraftを含め、新しい人数での実機（スマホ実機・Minecraft）は未検証。dry-runの通信試験と画面の描画だけで確認した。
- 4人目の色はキャラクター素材の赤（`--color-character-red`）を使った。発表資料・スマホの配色の確認は未実施。
- 役割の交換・編集（#47・#50）、観測に基づく提案（#58）は対象外。
