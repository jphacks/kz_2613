# 入力の初期値をONにし、手動でONにする手順をなくす

2026-10-25のユーザー指摘「操作設定からPC側でONにする設定はいらないのでは」に基づく判断（Issue #114）。[試作品の観測記録](2026-10-24-prototype-validated.md)の「注入モード off／test／on」の初期値 `off` より、この文書を優先する。

- **理由：** 試作品の `on` は前面のどのウィンドウにも合成入力を送る動作だったため、初期値を `off` にし、PCの前の人が明示的にONにしたときだけ送る安全策とした。入力先の確認（#19）が入った後は、協力プレイ中・P1の明示Ready・対象のゲームが前面・緊急停止キー、がそろわないと送らないため、手動のONは二重の確認になり、準備の画面で止まる手間だけが残っていた。
- **初期値：** `config.json` の `injectMode` を省略したときの初期値を `on` にした（`on` の送信条件は変えない）。`off`・`test` を明示した設定ファイルはそのまま使える。
- **緊急停止の後：** 緊急停止は今どおり入力を `off` にして一時停止する。PC画面（一時停止・準備の画面）に「入力を再開する」を出し、押すまでReady・再開できない。PCの前の人が安全を確かめる鍵として残す。
- **操作設定：** OFF/ONは「入力の一時停止（診断・緊急用）」の中へ移した。`test`（疑似ゲーム画面）は診断画面から使う。
- **弱めていない条件：** 前面の確認、P1の明示Ready、緊急停止、状態変化での全解放とepochの更新。

## 未検証

- PCアプリ・Minecraftでの実機確認（操作設定を開かずに協力操作が始まること、緊急停止キーの後に「入力を再開する」で再開できること）。dry-runの通信試験とヘッドレスChromeでの画面の確認だけで確かめた。
