# ゲームの起動を、メンバー・分担の決定の後に移す

2026-10-25のユーザー判断に基づく採用判断（Issue #109）。[ゲームの検出・起動](2026-10-25-game-detection-launch.md)の「選ぶと起動する」（#93・#94）より、この文書を優先する。

- **順序（ユーザー判断）：** ゲーム選択 → メンバー・操作分担の決定 → ゲーム起動 → ホストの準備 → P1の明示Ready → 協力操作。起動と協力操作の開始は区別し、起動の成功や接続人数だけで協力操作を始めない。
- **選択画面：** 選ぶだけで起動・前面化しない。主ボタン・Enterは分担の画面へ進むだけ。
- **分担の画面：** 主ボタン（PC画面のクリックとP1のリモコンのEnterで同じ）を「この分担で決定」→「ゲームを起動する」→「起動中…」（押せない）→「ゲームを準備する」の順に切り替える。起動に失敗・確認できなかったときは「もう一度起動する」と補助ボタン「手動で起動して準備へ」を出し、選択と分担を保ったまま再試行・手動準備できる。Minecraftなど自動起動できないゲームは、決定の後に手動起動を案内して準備へ進む。
- **ホストでの検証[H]：** 決定（`lineup`）はゲームと接続中のメンバーの組として持つ。画面は見ていたゲーム・メンバーを添えて決定を送り、ホストは今と一致するときだけ受け付ける（古い画面からの決定を受け付けない）。起動・準備・準備中のReadyは、決定が今の選択・接続者と一致するときだけ受け付けるので、画面を経ない直接の要求でも順序を迂回できない。
  - ゲームを選び直す（元のゲームに戻しても）・ロビーへ戻る・リセットで決定を消す。分担の画面から戻ると取り消す。
  - 参加者が変わると無効になり、同じメンバーに戻れば有効に戻る（分担はゲームとメンバーで決まるため、同じ組なら内容も同じ）。準備中に無効になったら、PC画面を分担の画面へ戻して決定し直させる。
- **起動の重複・起動済み：** 起動中の同じ要求は無視する。すでにウィンドウがある場合は起動し直さず前面にする（実機の判定のみ。dry-runの試験では未確認）。

## 未検証
