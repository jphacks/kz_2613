# Minecraftへの移行・復帰とセッションの維持（#35）

- 日付：2026-10-25（Claude Code）
- 状態：**[P]**（提案として実装。シミュレーションで確認済み、Minecraft・PCアプリの実機は未確認）。ユーザーの新しい判断があれば優先する。

## 決めたこと

1. **表示先と入力の許可を分ける。** 選んだゲーム（`game.title`）と表示中のPC画面は「表示先」で、入力を送ってよいかは進行（`coop`）・注入モード（`on`）・入力先のウィンドウ（前面がMinecraft）で決める。表示先が変わっても、入力の許可を推測で与えない。
2. **PCアプリへの手動復帰：** 協力プレイ中に、Alt+Tabなどで前面をPCアプリへ戻したら、ホストは全キー・マウスボタンを離して `paused`（`reason: app focus`）へ移す。P1のスマホはリモコンに戻り、PCアプリの画面を操作できる。自動では再開せず、P1のRESUMEで協力プレイへ戻る。
   - 判定は「PCアプリが前面になった瞬間」（false→true）だけ。START直後のように、PCアプリが前面のまま協力プレイが始まった場合は止めない。
   - **2026-10-25 追記 [E]：** デスクトップアプリ（Tauri / WebView2）の画面は、ほかのウィンドウが前面になっても `blur` を受け取らず、`document.hasFocus()` もtrueのままだった（実機で確認）。そのため画面の `focus` では手動復帰を検知できなかった。デスクトップアプリから起動したホストは、0.1秒ごとに確認している前面のウィンドウのプロセス名（`recooplay-desktop.exe`）で判定する。ブラウザで `/app` を開いた場合は従来どおり画面の `focus` を使う。
3. **ゲームの変更：** 選んだゲームはホストが保持する（PCアプリを再読み込みしても変わらない）。ロビー以外で別のゲームに変えたら、全解放して `lobby`（`reason: game change`）へ戻す。参加者・枠・役割はそのまま。
4. **フォーカス未確認時は送らない：** 常時ONでも、前面が入力先でない間は押下を受け付けない（#19の動作をそのまま使う）。

## 理由

- Minecraftから戻ったとき、P1が移動用の画面のままだとPCアプリを操作できない。全解放してリモコンへ戻すのが最も安全で、通信切断時の扱い（`paused`）とも揃う。
- ゲームの変更は進行中の操作の前提を変えるため、ロビーからやり直す（要件FR-018・AT-13：ENDで役割を保ったままロビーへ戻る）。

## 未確認

- WebView2（Tauri）のウィンドウで `focus`/`blur` が期待どおり届くこと。Minecraftとの実際の切り替え（#37）。
