## 製品概要

### 背景

#### 解決したい3つの課題

1. **運動が続かない**
   運動不足を感じていても、ランニングや筋トレは単調で続かない人が多くいます。「楽しいから動く」仕組みが必要です。

2. **ゲームは座って遊ぶものになりがち**
   ゲームに夢中な時間が、そのまま運動不足につながることがあります。

3. **「自分の好きな曲」で遊べるフィットネスゲームが少ない**
   リズムゲームやフィットネスゲームの多くは、あらかじめ用意された曲で遊ぶ形式です。ずっと聴き続けてきたお気に入りの曲で遊べれば、モチベーションは大きく変わります。

#### 着眼点

- 音楽には、拍・盛り上がり・静けさといった**「体を動かすための設計図」**がすでに含まれている
- 好きな曲なら、何度でも聴けるし、何度でも動ける
- カメラ1つあれば、**特別なデバイスなしで全身の動きを取得**できる時代になった

### 製品説明

> **音楽 × 骨格検知 × 運動**

**KINETUNE**は、手持ちの音楽ファイルを読み込むだけで、曲を自動分析し、**その曲専用の全身アクションステージ**を生成するゲームです。

コントローラーは不要です。カメラが捉えた**骨格(ボーン)の動き**だけで、画面の中の敵や障害物に立ち向かいます。

- 飛んでくるターゲットを**斬る**
- 迫る壁や弾を**避ける**
- 低いバーの下を**しゃがんで**くぐる
- 曲調に応じて、**ガラスを撃ち抜く** / **魔法を放つ** などアクションが変化する

遊び終わる頃には、ちょうどいい運動になっています。

### 遊び方

```
① 好きな音楽を読み込む  →  ② 曲を自動分析  →  ③ ステージ自動生成  →  ④ 全身で遊ぶ
```

1. **曲を選ぶ**
   手持ちの音楽ファイルをドラッグ&ドロップ(mp3 / wav / m4a など)
2. **自動分析**
   テンポ・拍・盛り上がり・曲構造・曲調を数秒〜数十秒で分析
3. **カメラの前に立つ**
   全身が映る位置に立ち、キャリブレーション(立ち姿・しゃがみ姿の記録)
4. **プレイ**
   曲に合わせて飛んでくるものを、斬る・避ける・しゃがむ
5. **リザルト**
   スコアに加えて、**運動量(動いた回数・しゃがんだ回数・推定消費カロリーの目安)** を表示

### 動きとアクションの対応

| 動き | 骨格での判定方法(例) | ゲーム内アクション |
| --- | --- | --- |
| **斬る** | 手首の速度・軌道の方向 | ターゲットを斬る、ガラスを割る |
| **避ける** | 肩・腰の中心位置の左右移動 | 飛んでくる壁や弾をかわす |
| **しゃがむ** | 肩・腰の高さの低下 | 頭上を通る障害物をくぐる |
| **パンチ** | 腕の伸展と手首の前方への速度 | 大きな敵・岩を破壊する |
| **ジャンプ** | 腰の高さの上昇 | 足元の波・床を飛び越える |
| **構える** | 両手の位置・ポーズの保持 | 魔法のチャージ・撃つ動作 |

### システム構成

| コンポーネント | 技術スタック(予定) | 役割 |
| --- | --- | --- |
| **音楽分析エンジン** | Web Audio API / Essentia.js(または Python + librosa) | BPM・拍・オンセット・帯域別エネルギー・曲構造の抽出 |
| **曲調判定** | 音響特徴量による分類(テンポ、スペクトル重心、エネルギー、調性など) | 曲に合うステージテーマの決定 |
| **ステージ生成** | TypeScript | 分析結果を、ターゲット・障害物・分岐のタイムラインに変換 |
| **骨格検知** | MediaPipe Pose Landmarker | 全身33点のランドマークをリアルタイム取得 |
| **動作判定** | TypeScript | 骨格の時系列から「斬る・避ける・しゃがむ」などを判定 |
| **ゲーム描画** | Three.js / Canvas | 3Dステージ・エフェクト・UI |

**処理フロー**

```
音楽ファイル
   ↓
[音楽分析] BPM / 拍 / 帯域別オンセット / 盛り上がり / 曲構造
   ↓
[曲調判定] アクション / ファンタジー / サイバー / 和風 / 静か ...
   ↓
[ステージ生成] ターゲット配置 + 分岐ポイント付きタイムライン(JSON)
   ↓
        カメラ → [骨格検知] → [動作判定]
                                  ↓
                    [ゲームエンジン] 判定・スコア・分岐の決定
```

### 特長

#### 1. どんな曲も、自分だけの全身アクションステージに変換

ポップス、ロック、EDM、アニメソング、クラシック、ゲーム音楽。どんなジャンルでも読み込めます。曲ごとにステージが自動で作られるため、**遊べる曲は無限**です。

#### 2. 音楽の構造が、そのままゲームの構造になる

| 音楽の要素 | ゲームへの反映 |
| --- | --- |
| **テンポ(BPM)** | ターゲットの速度・難易度の基準 |
| **キック(低音)のタイミング** | しゃがむ・パンチする大型ターゲット |
| **スネア(中音)のタイミング** | 斬る動作のターゲット |
| **ハイハット・高音域** | 小さな光の粒、細かい演出 |
| **盛り上がり(エネルギー)** | 敵の数・密度・エフェクトの強さ |
| **静かなパート** | 息を整える、ゆっくり腕を伸ばすなどのクールダウン要素 |
| **サビ・ドロップ** | ボーナスステージ・ルート分岐・大技 |

#### 3. 聴覚だけでなく、視覚でも音楽を楽しめる

プレイ画面は、曲の波形・帯域・盛り上がりと連動して**ステージ全体が変化**します。エンドレスに鑑賞するだけでも成立する「**音楽を見るためのビジュアライザー**」としても楽しめます。

#### 4. 曲の雰囲気でアクションが変わる

同じ「斬る」動作でも、曲調に合わせて**見た目と演出が変化**します。

| 曲調 | ステージテーマ(例) | アクションの見え方 |
| --- | --- | --- |
| **ロック / アクション系** | ガラスの街・ビル群 | ガラスを撃ち抜く・叩き割る。破片が音に合わせて飛び散る |
| **ファンタジー系** | 魔法の森・空中庭園 | 手から魔法を放つ。属性ごとに光が変わる |
| **EDM / サイバー系** | ネオン空間・電脳世界 | レーザーでデータを断ち切る |
| **和風・和楽器系** | 夜の城下町・竹林 | 刀で提灯や竹を斬る |
| **バラード / 静かな曲** | 星空・水面 | 流れる光をなでる・すくう。ストレッチ要素が強めのゆるい運動 |

#### 5. 特別な機器は不要

必要なのは **PC(またはタブレット)とカメラだけ**。コントローラーも専用デバイスも使いません。

#### 6. 運動として使える

- 動かした量を**運動量として可視化**
- **体力モード**(ゆっくり/標準/ハード)で、運動習慣のない人から運動好きの人まで対応
- 毎回違う曲で遊べるので、**飽きにくい**

### 分岐システム

「一本道のステージ」にならないよう、**3種類の分岐**を用意します。

#### ① 曲調による世界観の分岐(曲を読み込んだ時点で決定)

曲の分析結果によって、**ステージのテーマ・敵・アクションの種類**が分岐します(上の表のとおり)。同じ操作でも、曲が違えば別のゲームになります。

#### ② 曲構造による「ルート分岐」(プレイ中に発生)

サビ前や曲の切り替わりで**分岐ゲート**が現れます。体の動きで進むルートを選びます。

```
          ┌─ 左へ避ける  → ルートA: 斬撃ラッシュ(腕を大きく動かす)
分岐ゲート ─┼─ しゃがむ    → ルートB: 下半身ルート(しゃがみ・ジャンプ多め)
          └─ 中央を斬る  → ルートC: 魔法チャージルート(ポーズ保持+一撃)
```

- どのルートも**同じ曲に合わせて展開**されるので、音楽は途切れません
- ルートごとに**鍛えられる部位が異なる**ため、運動の幅が広がります

#### ③ プレイ内容による分岐(成績・状態に応じて)

- **コンボが続いた**場合 → ハイルート(演出が派手になる・ボーナスターゲット)
- **ミスが続いた**場合 → 回復ルート(ターゲットがゆるやかになる)
- **ラストの結果**によって、エンディング演出が変化

### 解決できること

- 運動が単調で続かない、という悩みを**「好きな曲で遊ぶ」楽しさ**で補う
- 専用機器なしで、**家のスペースだけで全身運動**ができる
- 毎回違う曲で遊べるため、**運動のマンネリ化を防ぐ**
- 運動の種類(腕・脚・体幹)を**曲とルートの選択で変えられる**
- 好きな曲を**ステージとして可視化**し、聴き込みの体験も豊かにする

### 今後の展望

#### もっと賢く

- **曲の自動分類精度の向上**: 歌詞・ムード・楽器構成も加味したテーマ判定
- **ユーザーの癖を学習**: 苦手な動きを検出して、ステージの難易度や動きの比率を調整
- **動作判定の高精度化**: 体格差・カメラ位置に左右されにくい判定

#### もっと運動として

- **運動プログラム化**: 「今日は下半身中心」「今日は軽めのストレッチ」などを曲から自動提案
- **運動量のトラッキング**: 日々の記録、週間の運動量グラフ
- **プレイプレイリスト**: 1曲ずつではなく、**プレイリストをまとめて「30分ワークアウト」に変換**

#### もっと遊びの幅を

- **ステージの共有**: 分析結果(タイムライン)だけを共有し、楽曲ファイル自体は共有しない仕組み
- **マルチプレイ**: 2人同時プレイ、離れた友人とのスコア対決
- **テーマの拡張**: 季節イベント、キャラクター、ユーザー作成のテーマ
- **VR / AR 対応**: ヘッドセット不要の現行版と互換性を保ちつつ拡張

### 注力したこと(こだわり等)

- **曲ごとに「別のゲーム」になる体験**: 単にターゲットが降ってくるだけでなく、曲調でアクションの世界観ごと切り替える
- **「楽しい」と「運動になる」の両立**: 動きの種類(腕・脚・体幹)のバランスを、曲の構造から自動で配分する
- **音楽に合うタイミング精度**: 拍・オンセット検出とターゲット配置を同期させ、**叩くタイミング=音が鳴るタイミング**になるようにする
- **骨格検知の安定性**: 判定にヒステリシス(判定のゆとり)を持たせ、誤判定やチラつきを抑える
- **音楽データの扱い**: 楽曲ファイルは基本的に**端末内で処理**し、外部サーバーへアップロードしない設計

## 既存作品との違い

調べた範囲では、**「手持ちの音楽を自動分析し、全身の骨格検知だけで、曲調に合わせてアクション自体が変わり、分岐もある」** という組み合わせの作品は見つかりませんでした。ただし、一部の要素が近い作品は存在します。

| 作品・プロジェクト | 近い点 | 本作との違い |
| --- | --- | --- |
| **Beat Saber + Beat Sage / SliceForge など** | 好きな曲から自動で譜面を生成して遊べる | VRヘッドセットとコントローラーが前提。譜面生成ツールはあくまで「Beat Saber用の譜面を作るツール」で、曲調によるアクション・世界観の変化や運動量設計は主目的ではない |
| **Melody's Escape 2** | 手持ちのMP3から障害物コースを自動生成して遊べる | キーボード操作。全身を使う運動が目的ではない |
| **Syncblade** | 好きな曲を読み込み、敵やイベントが自動生成される | コントローラー操作。骨格検知による全身運動ではない |
| **MediaPipe を使った運動・ゲーム系プロジェクト**(スクワットカウンター、Sword Build など) | カメラの骨格・手の検知で操作できる | 音楽の自動分析と連動していない、または手のみの操作 |
| **音楽ゲームの自動譜面生成研究** | 音響解析でノーツ配置を自動化 | 画面上のボタン操作の譜面生成が中心で、全身動作・運動を目的としていない |

### 本作ならではのポイント

1. **コントローラー不要**: カメラだけで全身(斬る・避ける・しゃがむ)を操作に使う
2. **運動を主目的にした設計**: 動きの種類のバランス、運動量の可視化、体力モード
3. **曲調によるアクション自体の変化**: ガラスを撃つ / 魔法を放つ / 刀で斬る など
4. **分岐**: 曲調・曲構造・プレイ内容の3種類の分岐

※ 上記は調査時点での確認結果で、すべての既存作品を網羅したものではありません。

## 安全への配慮

全身を使うゲームのため、安全面に配慮した設計にします。

- 開始前に**周囲のスペース確認**(両手を広げても物に当たらないか)を表示
- **ウォームアップ**と**クールダウン**を自動で挿入
- 激しい動き(ジャンプ・連続しゃがみ)は、**体力モードで頻度を調整**
- 一定時間ごとに**休憩の提案**
- 体調が悪いときや、持病・ケガがある場合は**無理をしない**よう案内
- カメラ映像は**端末内で処理**し、保存・送信しない
