Re:Cooplay（リコープレイ）は、**既存のPCゲームに、新しい協力プレイを後付けするツール**です。

普段は1人で操作するゲームのキャラクターを、2〜4人で分担して動かします。

移動する人、視点を動かす人、攻撃する人。**全員が操作の当事者になることで、いつものゲームに新しい協力体験が生まれます。**

ゲーム本体を改造することなく、手元のスマートフォンから新しい遊び方を楽しめます。

---

## 製品概要

### 背景(製品開発のきっかけ、課題等）

1人で遊ぶなら1人で操作する。複数人で遊ぶなら、それぞれが自分のキャラクターを操作するマルチプレイを選ぶ。それが一般的なゲームの楽しみ方です。

でも、**1つのキャラクターを動かすことそのものを、みんなで分担しても面白いのではないか。**

移動する人と視点を動かす人が違えば、思った方向へ進むにも声を掛け合う必要があります。失敗して笑うことも、息が合って成功することも、同じキャラクターを動かす全員の体験になります。

**ゲームの内容を変えずに、操作する人と協力の仕方を変える。**

Re:Cooplayは、既存のゲームにそんな新しい遊び方を加えたい、という発想から生まれました。

---

### 製品説明（具体的な製品の説明）

> **ゲーム体験 × Tech：1つのキャラクターを、みんなで動かす**

Re:Cooplay（リコープレイ）は、既存のPCゲームに新しい協力プレイを後付けするツールです。

参加者はそれぞれのスマートフォンをコントローラーとして使い、1つのキャラクターの操作を分担します。移動や視点、攻撃など、それぞれの操作を組み合わせることで、みんなで1つのキャラクターを動かします。

例えば、**3人でMinecraftを遊ぶ場合**、次のように担当します。

| プレイヤー | 担当する操作 |
|---|---|
| P1 | 移動・ジャンプ |
| P2 | 視点・カメラ操作 |
| P3 | 攻撃・アイテムの使用 |

敵が現れたら、移動担当が距離を取り、視点担当が敵を捉え、攻撃担当がタイミングを合わせて攻撃します。

それぞれが別の操作を担当するからこそ、自然と会話や協力が生まれます。

<br>

参加から共同操作までの流れは、次のとおりです。

1. **デスクトップアプリを起動する**  
   PCでRe:Cooplayを起動すると、参加用のQRコードが表示されます。

2. **スマホで参加する**  
   スマートフォンでQRコードを読み取り、Webアプリで参加します。最初に参加した人がホストとなり、スマホをPC画面のリモコンとして使えるようになります。

3. **遊びたいゲームを選ぶ**  
   ホストがスマホをリモコンとして操作し、PC画面に表示されたゲーム一覧から遊びたいゲームを選択します。

4. **操作を分担する**  
   PC画面で参加メンバーそれぞれの担当を確認し、操作分担を決定します。必要に応じて担当を入れ替えることもできます。

5. **ゲームを起動・準備する**  
   ゲームを起動し、プレイしたいステージやワールドなどを準備します。

6. **みんなで協力プレイ！**  
   準備ができたら、ホストがスマホから「Ready」を押します。各自のスマホが担当する操作画面に切り替わり、みんなで1つのキャラクターを操作できるようになります。

スマートフォンへの専用アプリのインストールは不要。1つのPCゲーム画面を共有しながら、複数人で協力プレイを楽しめます。PC側のセットアップについては[Windows構築・起動手順](docs/handoff/SETUP_WINDOWS.md)をご覧ください。

### 特長

#### 1. **1つのキャラクターを、みんなで操作する**

Re:Cooplayでは、**2〜4人で1つのキャラクターを共同操作**できます。参加人数に応じて操作を自動で分担し、ゲーム開始前や一時停止中には担当を入れ替えることもできます。

同じゲームでも、誰が移動や視点を担当するかによって、声の掛け合い方や連携の仕方が変わります。

**キャラクターを動かすだけでなく、仲間と息を合わせること自体がゲームの楽しさになります。**

<br>

#### 2. **いつものPCゲームに、新しい遊び方を後付け**

Re:Cooplayは、**ゲーム本体を改造することなく、新しい協力プレイを追加**できます。

ゲームごとの操作方法に合わせて共同操作を実現する仕組みを備えており、Minecraftでの共同操作に加え、さまざまなPCゲームへの展開を目指しています。

**遊ぶゲームを変えるのではなく、遊び方を変える。** 遊び慣れたゲームにも、新しい楽しさが生まれます。

<br>

#### 3. **スマホが、そのままコントローラーに**

PC画面に表示されたQRコードをスマートフォンで読み取れば、Webアプリから参加できます。**専用のスマホアプリや、新しいコントローラーを用意する必要はありません。**

ゲームの準備中は、ホストのスマホをPC画面のリモコンとして使用できます。共同操作を開始すると、参加者それぞれのスマホが**担当する役割に合わせたコントローラー**に切り替わります。

普段使っているスマートフォンだけで、参加から協力プレイまで楽しめます。

---

### 解決出来ること

**Re:Cooplayは、ゲームの操作そのものを、みんなで協力する新しい遊び方に変えます。**

| | これまでの遊び方 | Re:Cooplayで加わる遊び方 |
|:--|:--|:--|
| **キャラクターの操作** | 通常は1人が1つのキャラクターを操作する | 複数人が分担し、同じキャラクターを動かす |
| **協力の仕方** | 一般的なマルチプレイでは、各自のキャラクターを操作して協力する | 移動や視点など、1つひとつの操作から協力が始まる |
| **ゲームとの関わり方** | 1人が操作するゲームでは、その人が操作の中心になる | 共同操作する全員が、1つのゲーム体験の当事者になる |

想定しているのは、**仲間との掛け合いや協力、思いがけないハプニングを楽しむ人たち**。そして、**1人ではためらうゲームにも、誰かと一緒に挑戦してみたい人たち**です。

共同操作が生む楽しさは、ゲームによって異なります。

- **Minecraftでは、連携すること自体が遊びになる。** 3人で移動・視点・攻撃を分担し、敵との戦闘などで声を掛け合いながら攻略する楽しさが生まれました。Hack Dayのライブデモでは、その様子を見ていた会場が盛り上がり、懇親会で実際にMinecraftを体験してもらった際にも楽しんでもらえました。
- **ホラーゲームでは、怖さを一緒に引き受けられる。** チームメンバー2人で共同操作を試した際には、多少操作しづらい場面はあっても、1人で遊ぶときの心細さが和らぎ、2人とも操作に関わるプレイヤーとして楽しめると感じました。

**ゲームはそのままなのに、まるで別ゲー。**

同じゲームでも、誰とどう操作するかによって、まったく違う協力体験が生まれます。

---

### 今後の展望

Re:Cooplayが目指すのは、**既存ゲームの数だけ、みんなで遊ぶ新しい可能性を広げること**です。

- **より多くのゲーム・ジャンルへ：** Minecraftやホラーゲームで得られた楽しさを、アクションや探索ゲームなどにも広げ、タイトルごとの操作や遊び方に合わせた共同操作を楽しめるようにする。
- **自分たちらしい共同操作へ：** 操作の割り当てやボタン配置をさらに自由にカスタマイズし、同じゲームでも自分たちだけのルールで遊べるようにする。
- **離れていても一緒に：** 同じネットワーク・同じ画面で楽しむ共同操作を、離れた友達とも共有できるようにする。

---

### 注力したこと（こだわり等）

* **協力する過程そのものを面白くする：** 1人なら当たり前にできる操作も、仲間と分担すると声掛けやタイミング合わせが必要になります。思いどおりに動けないことも、息が合った瞬間も、一緒に楽しめる体験を大切にしました。
* **操作のしづらさを、不具合によるストレスにしない：** 分担するからこその難しさは遊びの一部です。一方で、入力の遅れや取りこぼしは面白さを損ないます。移動・視点操作や連打・長押しを自然に伝えることにこだわりました。
* **初めてでも参加しやすくする：** スマホでQRコードを読み取るだけで参加でき、PC画面で人数と担当を確認できます。準備中はリモコン、プレイ中は役割別のコントローラーとして使えるようにしました。
* **安心して開始・停止できるようにする：** みんなの準備が整ってから明示的に開始し、切断・一時停止・緊急停止のときには操作を止めることを重視しました。

## 開発技術

### 活用した技術

#### API・データ

* **Windows API `SendInput`：** 既存ゲームへキーボード・マウス入力を送る。
* **WebSocket / WebRTC DataChannel：** スマホからの操作入力と、PC・スマホ間の状態を送受信する。
* **ゲーム別の操作定義：** 担当する操作・キー割り当てをデータとして管理する。Minecraftの`options.txt`などの設定も利用する。

#### フレームワーク・ライブラリ・モジュール

* **Rust / Tokio / axum：** PCホスト、参加・通信・入力管理。
* **Tauri 2 / WebView2：** Windows向けのPCアプリ。
* **HTML / CSS / JavaScript：** PC画面とスマートフォン用の操作画面。
* **Node.js：** 通信シミュレーションや画面検証などの開発・テスト用。

#### デバイス

* **Windows PC：** ゲームの実行、通信と操作入力の統合。
* **Androidスマートフォン / iPhone：** ブラウザから参加し、担当別のコントローラーとして操作。
* **ローカルWi-Fiネットワーク：** PCと参加者のスマホを接続。基本的な共同操作に外部クラウドサーバーは不要。

### 独自技術

#### ハッカソンで開発した独自機能・技術

Hack Day（2026年10月24〜25日）に、複数台のスマートフォンで1つのPCゲームを動かすためのシステムを開発しました。[開発開始前のコミット](https://github.com/jphacks/kz_2613/tree/5acb0049e6)と[実装の差分](https://github.com/jphacks/kz_2613/compare/5acb0049e6...main)、[Hack Day開発ログ](docs/handoff/BUILD_LOG.md)で実装の根拠を確認できます。

* **複数人の入力統合と役割分担：** スマホから届いた操作を参加者の担当に応じて受け付け、1つのキャラクターへの入力に統合します。2〜4人に応じた分担と、プレイ開始前・一時停止中の役割交換にも対応しています。  
  [入力・セッション統合](apps/host-rs/src/hub.rs) ／ [操作の対応](apps/host-rs/src/controls.rs) ／ [Windows入力](apps/host-rs/src/input.rs) ／ [人数別の分担設計](docs/decisions/2026-10-25-variable-players.md)

* **リアルタイム通信と入力の整合性：** WebSocketとWebRTC DataChannelの両方を扱い、操作の重複や古い入力を防ぎます。視点の連続操作や短い連打、長押しにも対応しました。  
  [WebRTC通信](apps/host-rs/src/rtc.rs) ／ [通信プロトコル](docs/architecture/protocol.md) ／ [通信回帰試験](scripts/sim/protocol-sim.mjs)

* **ゲーム別の操作定義と役割別UI：** ゲームごとのキー設定・操作種類を扱い、Minecraftの設定の読み取りやSteam・Epic Gamesのタイトル検出、担当に応じたスマホ画面の生成を実装しました。操作定義の登録だけで、すべてのゲームでの動作を保証するものではありません。  
  [操作定義](docs/architecture/game-profiles.md) ／ [ゲーム検出](apps/host-rs/src/games.rs) ／ [キー設定](apps/host-rs/src/keybinds.rs) ／ [担当別の画面生成](apps/web-static/scripts/generated-controls.js)

* **安全な開始・停止と入力先の制御：** 参加・ゲーム選択・役割決定・準備の後にホストがReadyを押す方式を採用。対象ゲーム以外への誤入力を防ぎ、切断・一時停止・緊急停止の際にはキーやマウスボタンの入力を解放します。  
  [入力先の確認](apps/host-rs/src/focus.rs) ／ [役割交換](docs/decisions/2026-10-25-role-swap.md) ／ [開始手順](docs/decisions/2026-10-25-launch-after-roles.md)

操作入力は次の構成でPCゲームに伝わります。

```mermaid
flowchart LR
    P["スマートフォン（2〜4人）<br/>担当別の操作画面"] -->|"WebSocket / WebRTC"| H["Rustホスト<br/>参加・役割・入力統合"]
    D["PCアプリ<br/>Tauri"] <--> H
    C["ゲームごとの操作定義"] --> H
    H --> I["Windows API<br/>SendInput"]
    I --> G["既存のPCゲーム"]
```

| 構成要素 | 主な技術 | 役割 |
|:--|:--|:--|
| スマホ操作画面 | HTML / CSS / JavaScript | 参加、PC画面のリモコン、担当別のコントローラー |
| PCアプリ | Tauri / WebView2 | ゲーム選択、参加・分担の確認、開始準備 |
| PCホスト | Rust / Tokio / axum | 通信、参加状況、役割、ゲーム入力の統合 |
| リアルタイム通信 | WebSocket / WebRTC DataChannel | スマホからの操作と状態の送受信 |
| OS入力 | Windows API `SendInput` | ゲームへのキーボード・マウス入力 |

詳しくは[システム設計](docs/architecture/system-design.md)と[通信仕様](docs/architecture/protocol.md)を参照してください。
