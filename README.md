# Pose Canvas — 身体の動きが、共同のキャンバスになる。

> **JPHACKS2026 / kz_2613 企画候補 README（未開発・未採用）**  
> この文書は構想の提案であり、動作・性能・導入実績・チーム合意を示すものではありません。製品名・技術構成は仮称/暫定です。

**一言でいうと**：身体の動きが、共同のキャンバスになる。

## 製品概要

### 背景（製品開発のきっかけ・課題）

**対象ユーザー**：身体表現・絵や音で遊ぶ友人グループ。

絵を描く技能がなくても身体で作品を作ってみたいが、その場の動きは残りにくい。

この課題がどの程度頻繁に起きるのか、既存のやり方で解決できていないのかは未検証。まずは実際の利用場面を確認する。

### 製品説明（具体的な製品の説明）

**Pose Canvas** は、この場面で必要な行為だけを一つの体験につなげるプロダクトの構想である。

固定したスマホで自分たちを撮影→手や身体の動線が色の軌跡に変わる→複数人で作品を共同制作→動きを再生する。

利用前は「絵を描く技能がなくても身体で作品を作ってみたいが、その場の動きは残りにくい」という状態を想定する。利用後は、身体の動きが、共同のキャンバスになるという体験を通じて行動が変わることを目指す。ただし、その変化は今後のユーザー検証で確かめる。

### 特長

1. **利用場面から始める**：身体表現・絵や音で遊ぶ友人グループの具体的な一場面に対象を限定し、何でもできる総合アプリにはしない。
2. **最小の実動体験を先に証明する**：許可した被写体2人／端末を固定したカメラ／手か腕のキーポイント取得／ブラウザCanvasへ軌跡表示。
3. **既存手段との差を検証する**：既存のScreactとは異なり画面操作でなく協調的な表現を価値とする。手持ちスマホで自己骨格を検知する前提は置かない。

### 解決できること（仮説）

- 対象ユーザーが抱える「絵を描く技能がなくても身体で作品を作ってみたいが、その場の動きは残りにくい」を改善できる可能性がある。
- 使用前/使用後の違いを、説明だけでなく操作・結果の変化として確認できるようにする。
- 運用や導入の手間そのものが増えないかも評価する。

## 体験フローと画面

| 順番 | ユーザーに見せること | 実装・検証すること |
|---|---|---|
| 1. 開始 | 体験開始・対象や素材の選択 | 入力・権限・前提条件の確認 |
| 2. 実行 | 固定したスマホで自分たちを撮影 | 実データまたは明示したデモデータの取り込み |
| 3. 変化 | 手や身体の動線が色の軌跡に変わる | 体験の中心となる処理を完走させる |
| 4. 結果 | Before / After または体験結果 | 理解可能な出力とエラー表示 |

## システム構成（実装案）

```text
ユーザー入力 / センサー・素材
            |
            v
      端末側 UI と検証
            |
            v
      Pose Canvas のコア処理
            |
            v
      結果表示 / 音 / 体験
```

- **想定技術**：MediaPipe Hands/Pose・スマホカメラ・WebCanvas・端末内録画。
- **責任境界**：端末/OSに依存する機能、通信が要る機能、あらかじめ準備するデータを別々に検証する。
- **データの扱い**：同意と権限が必要な情報は収集範囲を限定し、権限不足・通信失敗時にも誤解を与えない。

## 90秒発表のデモ構成（台本案）

- **0–15秒｜背景**：誰がどんな場面で困る/何を面白くしたいのか、一例だけ提示。
- **15–65秒｜ライブ実演**：2人が両手を動かして共通キャンバスに2色の線を残し、作品を保存する。
- **65–80秒｜Before / After**：体験前と体験後の違いを実際の出力で示す。
- **80–90秒｜意義と制約**：どの条件下で動き、まだ何はできないのかを一言添える。

## 注力したいこと（実装上のこだわり）

- **中心価値**：既存のScreactとは異なり画面操作でなく協調的な表現を価値とする。手持ちスマホで自己骨格を検知する前提は置かない。
- **失敗しても成立する設計**：入力不正・権限拒否・通信断などをハンドリングし、成立しない機能はデモ時に無理に使わない。
- **測定と表現の峻別**：実測、推定、生成演出、手動入力を混同せずに表示する。

## 課題・反証条件

- 単眼で距離精度がない／被写体同士の遮蔽／既存ジェスチャーアートとの差／撮影同意。
- 競合比較は機能が存在するかだけでなく、「誰の不便がどれだけ残っているか」を基準に行う。
- **次の検証**：子どもや創作者が一般的なペイントアプリより共同制作を楽しめるか確認。
