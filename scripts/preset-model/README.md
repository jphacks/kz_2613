# 人数別プリセットのモデル（BERT風）

> **学習データはリポジトリに置いていません（2026-11-13）。** `scripts/preset-model/data/`（注釈 `labels.json`、評価の正解 `github-eval-57.json`・`human-*.json`、このPCで読んだ操作 `real-games.json`、`claude-games.txt`）は Git の対象外です。学習・評価をするときは、管理者からこのフォルダーを受け取って置いてください。以下の説明に出てくる `data/` のファイルは、このフォルダーのことです。

ゲームの操作一覧を読み、2〜4人用の分担（プリセット）を作るための小さなエンコーダです。学習はこのフォルダのPythonで行い、推論はRustホスト（`apps/host-rs/src/preset_model.rs`）が、プリセットのないゲームを一覧で見つけたときに1回だけ行い、結果を保存します（#431）。重みはexeに埋め込むので、配布物に依存は増えず、インターネットも使いません。

## 学習データ：実在のゲームだけ・ローカルで読める情報だけ

合成したゲームは使いません（比較用に `--synthetic` で混ぜられます）。データは次の2つです。

| 情報源 | ゲーム | 読んだもの |
|---|---|---|
| このPCのゲームのファイル（`build_dataset.py`） | Minecraft | `Options.class` の操作名、言語ファイル `ja_jp.json` の公式の日本語名、`options.txt` のキー（このPCの設定なので初期値と違うことがある） |
| | Terraria | `input profiles.json` の操作名とキー |
| | Goose Goose Duck | ゲームに埋め込まれた Unity Input System の定義（操作名・キー） |
| | R.E.P.O. | 列挙型 `InputKey` の操作名、`DefaultKeyBindings.es3` の開発者の初期キー |
| | Core Keeper | `Pug.Other.dll` の .NET メタデータにある `RewiredConsts.Action` の定数名（キーなし） |
| リポジトリの手作りの定義（`apps/game-profiles/`、状態が template 以外） | 上の5本と、Lethal Company・Garry's Mod・Stardew Valley・Team Fortress 2・Left 4 Dead 2・Portal 2・Counter-Strike 2・Valheim・Among Us | 日本語ラベル・キー |

`build_dataset.py` は、このほかに次の形式も読みます（このPCには該当するゲームがまだ入っていないので、見本のフォルダでだけ確かめています：`python scripts/preset-model/test_readers.py`）。

- `extract.mjs` が読めるほかのゲーム（Unity Input System の埋め込み定義・.NET の列挙型・設定ファイル）
- Source：`scripts/kb_act.lst`（操作と表示名の翻訳キー）、`resource/*_english.txt`・`*_japanese.txt`（英語・日本語の表示名）、`cfg/config_default.cfg`（初期キー）。VPK に入っている場合も読む
- Source 2：`.vcfg` のキー設定（VPK の中も）
- Unreal Engine 3：`Config/*Input.ini` の `Bindings=(Name=…,Command=…)`

ゲームを入れて `build_dataset.py` を実行すると、読めたゲームと注釈のない操作の数が表示されます。

合わせて実在のゲーム14本、578操作です。tModLoaderはTerrariaと同じ内容なので除きました。Outlastは操作ではないデータ（ライトマップの設定）しか取れなかったので除きました。ゲームの読み取りは `scripts/profiles/extract.mjs` と同じく読むだけで、ゲームのコードは実行しません。`data/real-games.json` にはこのPCのパスやユーザー名を含めません。

ジャンルの型から作った定義（488本）は学習に使わず、実際に推論する対象への当てはまりを見る評価にだけ使います。

### Claudeが知識から書いた実在のゲーム（`data/claude-games.txt`）

上の14本だけでは、初めて見る操作名（`Honk`・`Tumble`・`Touchpad` など）への当てはまりが足りませんでした（1ゲームずつ外した評価でカテゴリ69.0%）。そこで、ユーザーの依頼により、Claude Code が自分の知識から実在のゲーム79本（FPS・3Dアクション・サバイバル・プラットフォーマー・見下ろし型・レース・格闘など）のPCの初期キー設定を書き、学習に加えました。合わせて122件・2,370操作です。43本には日本語名の版も付けています。

- インターネットは使っていません。ゲームのファイルも読んでいません。**記憶から書いたので、操作名・キーに誤りが混ざる可能性があります。**
- 日本語名は Claude が付けたもので、公式の表記とは限りません。
- 評価に使う14本は、答えが漏れないよう書いていません。
- `--no-claude` を付けると、このデータを使わずに学習します（比較用）。

### 注釈

`data/labels.json` に、各操作がどの概念（`lexicon.py` の `CONCEPTS`：前進・ジャンプ・撃つ・武器1・メニュー…）かを書いています。手作りの定義は、辞書で引けないラベルの分だけ書いています。**注釈はClaude Codeが操作名・キー・ゲームの仕組みから付けたもので、人の確認は済んでいません。** `ui` は遊びの操作ではない画面・設定・デバッグの操作です。

注釈のない操作があると `train.py` は止まります。`build_dataset.py` で新しいゲームが増えたら、`labels.json` に書き足してください。

## 構成

| 項目 | 内容 |
|---|---|
| 入力 | 操作ごとに `label`・`id`・`bind` の文字n-gram（FNV-1aで2048個に振り分け、平均）＋初期キー＋種類 |
| 本体 | BERTと同じpost-LNのTransformerエンコーダ 2層（隠れ32次元・4ヘッド・FFN 64）。位置埋め込みは使わず、操作の集合として読む |
| 出力 | ①カテゴリ（移動・視点・行動・持ち物・メニュー・会話）、②2つの操作を同じ人が持つべき確率、③同じまとまりの中で同じ軸か（方向の縦と横） |
| 自己教師ありの課題 | BERTの穴埋めと同じく、15%の操作のキーを伏せて名前と周りの操作から当てる（キーはゲームの開発者が決めた実データ）。15%の操作の名前を `[MASK]` にしてカテゴリを当てる |
| 水増し | 実データが少ないので、1本につき150通り、操作の一部を落とし、ラベル・設定名・キーを時々消して学習する |

グループ名（`movement` など）は入力に使いません。モデルは送ってよい操作を増やしません。配るのは操作定義で役割案がP1〜P3の操作だけです。2〜4人への組み立ては `preset_model.rs` が決まった手順で行います（`docs/game-profile-specification.md`）。

## 実行

```
python -m venv .venv
.venv\Scripts\python -m pip install --index-url https://download.pytorch.org/whl/cpu torch==2.6.0
.venv\Scripts\python -m pip install numpy
python scripts/preset-model/build_dataset.py          # このPCのゲームから data/real-games.json を作り直す（任意）
.venv\Scripts\python scripts/preset-model/train.py     # 学習・書き出し
.venv\Scripts\python scripts/preset-model/train.py --cv --copies 60 --epochs 20   # 1ゲームずつ外した評価
```

書き出したら `cd apps/host-rs && cargo test --release preset_model` を実行します。Rustの推論がPythonと一致するか（`preset-model-parity.json`）と、全定義の2〜4人分の分担を確かめます。分担の表は `cargo test --release preset_table -- --ignored --nocapture` で出力できます。

torch 2.11をPython 3.13で読み込むと、ソースの解析（`torch/_jit_internal.py`）で `IndentationError` になる環境がありました。その場合は上のように専用のvenvで2.6を使います。

**特徴量の作り方を変えるときは、`train.py` の `words`・`features`・`featurize` と `preset_model.rs` の同名の関数を必ず両方直します。** 一致しなくなると `inference_matches_python` が失敗します。

## 評価（2026-11-08、DGXで学習、種 20261108）

### 1ゲームずつ外した評価（交差検証）

評価に使う14本のうち1本を外して学習し、外したゲームで測ります（`--cv --copies 60 --epochs 20`、並列にするときは `--cv-game <ID> --threads 1`、集計は `cv_summary.py`）。「遊び」は、振り分けに使う操作（移動・視点・行動・持ち物）どうしの組だけで測った値です。メニュー・会話はP1のリモコンのままで配らないので、プリセットの良し悪しには関わりません。ゲームごとの平均（1本平均）で示します。

| 学習データ | カテゴリ | 遊び：同じ人の判定 | 遊び：同じまとまりの再現率 | 遊び：まとまり内の軸 |
|---|---|---|---|---|
| A 実在14本だけ（`--no-claude`） | 81.3% | 82.5% | **93.7%** | 76.5% |
| **B ＋Claudeが書いた79本（既定）** | **84.9%** | **93.3%** | 88.5% | **92.8%** |
| C ＋Claudeが書いた79本＋IDの書き方の水増し（`--style-aug --claude-copies 10`） | 83.4% | 91.6% | 90.5% | 91.6% |

Bを採用しました。内訳は次のとおりです（設定B）。

| 外したゲームの種類 | カテゴリ | 遊び：同じ人 | 遊び：再現率 | 遊び：軸 |
|---|---|---|---|---|
| 手作りの定義だけの9本 | 97.2% | 98.3% | 97.8% | 98.2% |
| このPCの生データを含む5本 | 62.8% | 84.3% | 71.7% | 83.0% |

- 全部の組で測ると、Bの再現率はAより下がって見えます（89.6%→80.4%）。原因はUI・メニューの操作どうしの組です。Goose Goose Duckだけで約70個のUI操作があり、組の数を占めます。遊びの操作だけで測ると、Bは同じ人の判定と軸が大きく上がっています。
- IDの書き方の水増し（C）は、ゲームのファイルにある名前（`GameControls/MoveUp` など）に慣れさせるためのものでした。再現率はやや上がりましたが、ほかの値は下がったので使いません。
- 生データの弱点は、R.E.P.O.（遊びの再現率37%）とCore Keeper（64%）です。R.E.P.O.の左クリックのGrab（つかむ）を、注釈では「使う」のまとまりに入れましたが、モデルは「攻撃」側と見ています。判断が分かれる操作です。Core Keeperはキーが取れておらず、名前だけが手がかりです。

### Project Winter を加えたとき（実在15本）

Rewired の設定から Project Winter（72操作、キーあり49）を読み、加えました。元の生データ5本で比べると、1本平均でカテゴリ62.8%→62.7%、遊びの同じ人の判定84.3%→83.2%、再現率71.7%→72.4%、軸83.0%→84.4% と、ほぼ変わりませんでした（誤差の範囲）。1本・72操作では足りず、しかも約6割はUIの操作です。Project Winter を外して評価すると、カテゴリ51%、遊びの同じ人の判定91%、再現率59%でした。生データへの汎化を上げるには、生データのゲームをまとまった数で増やす必要があります。

### GitHub の操作定義を加えたとき

ユーザーの判断（配布物がオフラインならよい、学習に使うだけならライセンスも問題ない）を受け、`collect_github.py` で GitHub から Unity の `.inputactions` と Godot の `project.godot` を4,950件集め、`github_dataset.py` でテンプレートの使い回しなどを除いて2,538件（21,032操作）にしました。集めたファイルは Git の対象外の `data/local/` に置き、リポジトリには取得の手順と注釈だけを残しています。注釈のないものは、キーを伏せて当てる自己教師ありの課題だけに使います。無作為に選んだ22本に Claude が注釈を付けました（`labels.json` の `github:`）。

| 評価 | 指標（遊びの操作どうし） | GitHubの注釈なしデータなし | あり |
|---|---|---|---|
| GitHubの注釈付き22本（学習に不使用、`--holdout-github`） | 同じ人 / 再現率 / 軸 / カテゴリ | 90.3% / 76.0% / 88.0% / 80.1% | 90.4% / 75.2% / 89.5% / 81.4% |
| 15本の交差検証のうち生データ6本（1本平均） | 同じ人 / 再現率 / 軸 / カテゴリ | 84.4% / 70.2% / 83.6% / 60.8% | 87.3% / 66.0% / 81.9% / 65.5% |

注釈なしのデータで伏せたキーの予測は41.6%→67.3%と上達しましたが、振り分けに使う判断にはほとんど移りませんでした。注釈なしのデータをこれ以上増やしても伸びは見込めません。伸ばす余地があるのは、注釈付きの生データと評価用のデータです（評価に使えるのが生データ6本＋GitHub 22本だけで、±1〜4ポイントの差は誤差に埋もれます）。

最終モデルにはGitHubのデータを含めました。プリセットの表では、Terrariaの3・4人用でカーソルが視点の担当になり（従来の課題が解消）、Cupheadの3人用が「左右＋ジャンプ／上下／攻撃」になりました。一方で、Forzaの3人用でアクセルとブレーキが別の人に分かれるようになりました（レースのデータが少ないため）。

### 注釈付きの生データを増やしたとき（GitHub 57本）

注釈なしのデータが効かなかったので、GitHub のゲームへの注釈を35本足しました（乗り物系を中心に、合わせて57本・582操作）。1台で2人が遊ぶもの、ポインター操作が中心のもの、操作名がキー名だけのものは除きました。57本を4組に分け、ほかの組で学習して残りの組で評価しました（`--gh-folds 4`）。

| 学習データ（57本を初見として評価、1本平均、遊びの操作どうし） | カテゴリ | 同じ人 | 再現率 | 軸 |
|---|---|---|---|---|
| 注釈付きの生データなし（`--holdout-github`） | 79.7% | 87.3% | 74.5% | 89.1% |
| ほかの組の注釈付き生データあり | **85.8%** | **88.5%** | **83.2%** | **92.9%** |

注釈付きの生データ（約430操作）は、注釈なしのデータ（約2万操作）と違ってはっきり効きました。乗り物系10本では、カテゴリ62%→76%・軸62%→72%と上がった一方、再現率は30%→39%で弱いままです（乗り物の操作名はゲームごとにばらばら）。最終モデルでは、Forzaの3人用が「ハンドル／アクセル・ブレーキ／サイドブレーキ・ブースト」に戻りました。

### 割り引いて見るべき点

- 評価に使えるのは実在の14本だけで、ゲームの生データは5本です。
- 評価の正解（`labels.json`）と、学習に加えた79本（`claude-games.txt`）は、どちらもClaudeが書きました。同じ判断の癖が両方に入るので、数字が実際より良く出ている恐れがあります。人の確認は済んでいません。
- 測っているのは操作の意味を当てられるかで、できたプリセットが遊びやすいかは実機で確かめていません。
- ホストは今、初めて見るゲームのファイルを読みません（定義がなければ汎用の定義を使う）。生データへの弱さは今の動作には出ませんが、ホストが起動時にゲームを読むようにするなら改善が必要です。
